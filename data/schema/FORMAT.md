# Формат данных avito — версия 1

Единый формат данных магазина. Его читают и пишут **бот** (`avito/bot`, Python) и **HUB BRO** (`avito/hub-bro`, веб) —
только через сервер данных (`avito/data/server`), никогда не файлами напрямую. Клиенту ставят бота, хаб или оба:
формат один, у каждого продукта свои файлы-владельцы.

Проверка формата — `data/schema/validate.mjs` (её вызывает сервер при каждой записи). Перевод старых данных —
`data/schema/migrate-legacy.mjs`. Меняется формат — поднимается `version` файла, пишется миграция, правится этот
документ и журнал внизу.

## Общие правила

1. **Файлы** лежат в `data/store/` (у каждого клиента свой store). Каждый — JSON-объект с полями
   `format` (имя файла без `.json`) и `version` (номер версии формата). Неизвестную версию сервер не примет, а клиент
   не должен читать.
2. **id** — строки. У товаров и категорий — читаемый slug (`klesh`, `jeans`): латиница, цифры, `_`, `-`, до 40 знаков,
   не меняется никогда. У остального — случайные (`newId()` хаба). У заказов и объявлений — номера Авито.
3. **Связи только по id.** Названия — для людей, их можно переименовывать без последствий.
4. **Размер** — номер строкой: `"30"`. Буква — отдельно, в шкале (`sizeScale`). Сравнение — строго `===`.
   На экране и в чате: `30 (M)`.
5. **Даты:** момент — ISO (`2026-11-25T09:45:41.408Z`), день — `YYYY-MM-DD`.
6. **Деньги** — рубли, число.
7. **Неизвестные поля** не удаляются при перезаписи: клиент меняет только то, что знает, остальное переносит как есть.
8. **Запись целиком** и с версией сервера (`baseRev`): кто-то успел раньше — 409, перечитать, применить свою правку
   к свежим данным, отправить снова. Хаб сейчас при 409 свою правку выбрасывает — это допустимо, но лучше применять заново.

## Кто чем владеет

| Файл | Что | Пишет | Читает |
|---|---|---|---|
| `catalog.json` | шкала размеров, категории, товары с описанием, сетками, фото, ручным наличием | бот (приложение менеджера), хаб | оба |
| `stock.json` | поставки, остатки по размерам, джинсы под заказами | хаб | оба (бот — только наличие) |
| `orders.json` | заказы Авито | хаб | хаб |
| `listings.json` | объявления Авито → товар | хаб | оба |
| `printBatches.json` | партии печати бирок | хаб | хаб |
| `shop.json` | магазин: название, откуда наличие, время отправки, порядок служб | оба | оба |
| `hub.json` | только хабу: отображение склада, черновики поставок | хаб | хаб |
| `log.json` | общая история изменений настроек и каталога | оба (дописывают) | оба |
| `files/` | фото товаров и картинки сеток | оба | оба |

Только бот = `catalog`, `shop`, `log`, `files`. Только хаб = всё, кроме полей бота в `catalog` (они просто пустые).

## catalog.json

```jsonc
{
  "format": "catalog", "version": 1,
  "sizeScale": [ { "size": "25", "label": "2XS" }, { "size": "30", "label": "M" }, … ],
  "categories": [ Category ],
  "products":   [ Product ]
}
```

**`sizeScale`** — все допустимые размеры магазина по порядку (единственный источник правды по номерам). `size` уникален,
`label` — буквы по умолчанию (может быть пустым). Свои буквы у категории — `Category.labels`, они главнее.
Буквы размера товара = `labels` его категории, иначе `label` из шкалы; показывается «30 (M)». Любой размер в остальных файлах
обязан быть из шкалы.

### Category

| Поле | Тип | Смысл |
|---|---|---|
| `id` | slug | |
| `name` | string | «Джинсы». Уникально без учёта регистра |
| `sizes` | size[] | Шаблон размеров для новых товаров, по порядку |
| `thresholds` | `{ lowMax, midMax }` | Пороги цвета остатка (хаб). По умолчанию 5 / 10 |
| `labels` | `{ [size]: string }`? | **Буквы размеров этой категории**: `{"30": "M", "31": "L"}` — у каждой категории своё соответствие. Размер из шкалы, буквы `0-9 A-Z` до 4 знаков. Нет буквы здесь — берётся `label` из `sizeScale` (запасная, общая для магазина) |

Порядок массива = порядок категорий (очередь печати хаба).

### Product

| Поле | Тип | Кто пишет | Смысл |
|---|---|---|---|
| `id` | slug | оба | Не меняется. Для старых товаров бота = имя папки (`klesh`) |
| `name` | string | оба | «Клёш». Уникально без учёта регистра |
| `categoryId` | id | оба | Категория |
| `code` | string? | хаб | Код на бирке, 1–4 знака `[0-9A-ZА-ЯЁ]`, уникален («КЛ») |
| `archived` | bool? | хаб | В архиве: не виден на складе, в поставке и боту (бот считает «нет в наличии») |
| `sizes` | size[] | оба | Размеры товара **по порядку показа** |
| `hiddenSizes` | size[]? | хаб | Скрытые на складе (только пустые) |
| `thresholds` | `{ lowMax, midMax }`? | хаб | Свои пороги, иначе — категории |
| `packs` | `{ id, name, sizes: size[] }[]`? | хаб | Пачки для ввода поставки, по 1 штуке каждого размера |
| `match` | string[] | бот | Слова в названии объявления, по которым бот узнаёт товар, в нижнем регистре. Уникальны среди товаров |
| `botKey` | string? | бот | Старый внутренний ключ бота (`клеш lgb flared bootcut zara`): на него завязаны чаты в `live/state.json`. Новым товарам не нужен |
| `description` | Description | бот | Что бот рассказывает о товаре |
| `sizeTable` | SizeTable? | бот | Размерная сетка в см |
| `sizeHW` | SizeHW? | бот | Размер по росту и весу |
| `photos` | file[] | бот | Фото на человеке, по порядку отправки (имена файлов в `files/`) |
| `chart` | file? | бот | Картинка размерной сетки |
| `availability` | `{ inStock: bool, outSizes: size[] }` | бот | Ручное наличие: работает, когда `shop.stockSource = "manual"` (см. «Наличие») |

**Description** — `{ material?, composition?, density?, legOpening? }`, строки или `null`:
- `material` — что бот говорит по умолчанию («98% хлопок»);
- `composition` — полный состав, только если переспрашивают («98% хлопок, 2% полиэстер»);
- `density` — ответ на «плотные? тянутся?»;
- `legOpening` — ответ на «какой выход?», когда размер не назван.

**SizeTable** — сетка в сантиметрах, обхваты в половину:
```jsonc
{
  "columns": [ { "key": "полуталия", "title": "Полуталия" }, … ],   // key: нижний регистр, пробелы → _, ё → е
  "rows": { "30": { "полуталия": 36, "длина_по_внеш_шву": 114 }, … }  // размер → значения; нет значения — нет ключа
}
```
Колонки у товаров разные. Размер со строкой в `rows` нельзя убрать из `sizes` товара (сервер не примет) —
хаб такой размер не удаляет, сначала бот убирает строку из сетки. Бот понимает по ключам: `полуобхват_талии` | `полуталия`, `полуобхват_бедер`,
`полуобхват_одного_бедра`, `выход` | `полувыход`. Размеры в `rows` — из `sizes` товара.

**SizeHW** — размер по росту и весу:
```jsonc
{ "heights": [0, 164, 172, 177, 182],      // начала полос роста, см, по возрастанию; 0 = «меньше следующей»
  "weights": [0, 41, 44, …],               // начала полос веса, кг
  "cells":   [ ["25", "26", …], [null, "26", …] ] }   // [рост][вес]: размер или null (= бот не называет, чат менеджеру)
```

**file** — имя файла в `files/`: `<productId>_<n>.<ext>` для фото, `<productId>_size_chart.png` для сетки
(бот отличает сетку от фото по `size_chart` в имени — не менять).

## stock.json (владелец — хаб)

```jsonc
{
  "format": "stock", "version": 1,
  "batches":  [ Batch ],
  "products": { "<productId>": { "<size>": SizeStock } }
}
```

**Batch** (= поставка) — как в хабе сейчас (WAREHOUSE.md), плюс `productId`:
`{ id, productId, name, date, from, total, price, delivered: { size, qty }[], addedAt, cancelledAt?, packs?: { name, count }[] }`.

**SizeStock** — `{ stock: { batchId, qty }[], units: Unit[] }`:
- `stock` — безликие джинсы на полке по поставкам, нулевых записей нет;
- **Unit** — `{ order, orderDate, status, batchId, pickupPoint? }`, `order` = id заказа (номер Авито), `orderDate` = `ДД.ММ`,
  `status` ∈ `reserve | returnStock | sent | delivered | returnTransit`.

Размер, которого нет в `products[id]`, = 0 на полке и без заказов. Правила склада (WAREHOUSE.md, «Правила») не
меняются: остаток меняется только движениями.

## Наличие (для бота)

`shop.stockSource` решает, откуда бот берёт наличие:

| `stockSource` | В наличии размер `s` товара `p`, если… |
|---|---|
| `"warehouse"` (стоит хаб) | `p` не в архиве и на полке `sum(stock.products[p][s].stock[].qty) > 0` |
| `"manual"` (только бот; так у нового магазина. Хаб сам не переключает — `warehouse` ставится при установке хаба) | `p.availability.inStock` и `s` не в `p.availability.outSizes` |

Товар в наличии, если в наличии хотя бы один его размер. Сервер данных недоступен — бот работает по последней
сохранённой копии; копии нет — считает «в наличии» (как сейчас для неизвестного товара), чтобы не отказывать покупателям.

## orders.json, listings.json, printBatches.json (владелец — хаб)

```jsonc
{ "format": "orders",       "version": 1, "orders":   [ Order ] }
{ "format": "listings",     "version": 1, "listings": [ Listing ], "syncedAt": "…"? }
{ "format": "printBatches", "version": 1, "batches":  [ PrintBatch ] }
```
Поля — как в хабе сейчас (`shared/orders/types.ts`, `shared/listings/types.ts`, `shared/fulfillment/types.ts`), кроме:
- `Order.productId?` — **связь с товаром по id** (раньше по названию в `product`). `Order.product` остаётся снимком
  названия для истории и показа;
- `Listing.productId` вместо `Listing.modelId`.

## shop.json

```jsonc
{
  "format": "shop", "version": 1,
  "name": "BRO x BRO SHOP",                        // может быть пустым у нового магазина
  "stockSource": "warehouse",                       // или "manual"
  "cutoffs": { "weekday": "19:00", "weekend": "18:00" },   // до скольки (МСК) заказ уходит сегодня
  "serviceOrder": ["yandex", "avito", "cdek", "post", "fivepost", "dpd"]   // порядок служб в очереди печати (хаб)
}
```

## hub.json (только хаб)

```jsonc
{ "format": "hub", "version": 1,
  "display": { "showZeroOnTiles": true, "showIncoming": true, "tileRows": 2 },
  "drafts": [ DeliveryDraft ] }     // как в хабе: DeliveryLine.productId; новый товар — newProduct { name, categoryId, categoryName? }
                                    // categoryName — категория, которой ещё нет (создастся при добавлении поставки)
```

## log.json

```jsonc
{ "format": "log", "version": 1,
  "entries": [ { "id": "…", "at": "ISO", "source": "hub" | "bot", "text": "«Клёш»: пороги 5 / 10 → 10 / 15" } ] }
```
Новые сверху, хранится до 2000 записей.

## Сервер данных (кратко; подробно — `data/server/README.md`)

```
GET    /api/state                 → { revs: { catalog: 3, stock: 7, … } }
GET    /api/state?key=catalog     → { value, rev, savedAt }
PUT    /api/state?key=catalog     { value, baseRev } → { rev, savedAt } | 409 { conflict, value, rev, savedAt } | 422 { errors }
GET    /api/files/<name>          → файл
PUT    /api/files/<name>          тело — байты файла → { name, size }
DELETE /api/files/<name>
```
Ключ доступа — заголовок `x-hubbro-key`, если задан.
