# HUB BRO

Кабинет для магазинов на Авито: заказы → очередь комплектации с группировками → печатные партии →
печать официальных транспортных этикеток на складском принтере через Print Agent.

ТЗ: `HUB_BRO_TZ_v1.0.docx` (v1.0, 04.11.2026).

## Как устроено

```
Авито API ──► backend (FastAPI) ──► SQLite/Postgres + storage/ (PDF этикеток)
                 ▲      ▲
   веб-кабинет ──┘      └── Print Agent на ПК с принтером (сам ходит на сервер по HTTPS)
   (React, любой браузер)          └──► системная очередь печати ──► термопринтер
```

- `backend/` — API, импорт заказов, резервы, партии, задания печати. Документация API: `/docs`.
- `web/` — одностраничный кабинет (React + TypeScript + Vite).
- `agent/` — Print Agent, только стандартная библиотека Python. На Windows печатает через SumatraPDF (`-print-settings noscale`), на macOS/Linux через `lp`. PDF печатается без масштабирования, транспортный QR не трогаем.

## Статус интеграции с Авито

Ключи рабочие: токен выдаётся, аккаунт «BRO x BRO SHOP» (444530615) виден.
API заказов отвечает 403, пока не подключена **Авито Доставка для бизнеса** (реквизиты + тариф).
До этого работаем на заглушке (`AVITO_MODE=mock`): тестовые заказы двух магазинов и тестовые PDF
с крупной пометкой «ТЕСТ — НЕ ДЛЯ ОТПРАВКИ». После подключения дописываем `backend/app/avito/client.py`
по реальному ответу API.

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cp .env.example .env
cd web && npm install && npm run build && cd ..
.venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8000
```

Кабинет: http://localhost:8000, вход `admin@hubbro.local` / `admin`.
Для разработки фронта с горячей перезагрузкой: `cd web && npm run dev` → http://localhost:5173.

Тесты: `cd backend && ../.venv/bin/python -m pytest`.

## Подключение принтера

1. В кабинете: «Принтеры» → «Добавить станцию» — появится код привязки.
2. На компьютере с принтером:
   ```bash
   python hubbro_agent.py pair --server https://адрес-кабинета КОД
   python hubbro_agent.py run
   ```
3. «Тестовая печать» — рамка 80×80 мм должна выйти ровно 80×80.

На Windows рядом с агентом положить `SumatraPDF.exe`. Сборка в один `.exe` и автозапуск — следующий шаг.

## Что готово (P0 из ТЗ)

- Несколько магазинов, роли, вход, журнал действий.
- Импорт с защитой от дублей (`source + account_id + id заказа`), хранение исходного payload.
- Сопоставление объявление → SKU, статус «Нет SKU» блокирует сборку.
- Резервы: одну единицу нельзя зарезервировать под два заказа (условный UPDATE).
- Очередь комплектации: группировка по магазину, модели, размеру, ячейке, ПВЗ, сроку в любом порядке;
  счётчики не зависят от фильтра.
- Печатные партии: предпросмотр, проверка (не отменён, не в другой партии), печать, повтор сбойных, закрытие.
- Повторная печать одной этикетки с причиной, заказ не дублируется.
- Отмена в Авито — снятие резерва, этикетка недействительна; смена ПВЗ — старая этикетка аннулируется.
- Корректировка остатков, автоматическая разблокировка ожидающих заказов.
