# HUB BRO — архитектура веб-кабинета

Стек: Vite + React 18 + TypeScript, react-router для разделов, CSS Modules для стилей. Код — в `web/`.

## Папки

```
web/src/
├── main.tsx              точка входа: роутер, глобальные стили
├── app/                  каркас приложения
│   ├── App.tsx           роуты
│   ├── routes.tsx        единый список разделов (путь, название, страница)
│   └── layout/           общий макет: боковое меню + рабочая область
├── features/             разделы, по папке на каждый
│   ├── labels/           Пульт (печать и расклейка партий)
│   ├── picking/          Комплектация
│   ├── stock/            Склад
│   ├── orders/           Заказы
│   ├── listings/         Объявления Авито и привязка к моделям склада
│   └── settings/         Настройки: Авито, Telegram, принтер, позже авторизация
└── shared/               то, что используется в нескольких разделах
    ├── orders/           заказы: типы, статусы, useOrders() — их читают заказы, комплектация, пульт
    ├── stock/            склад: типы, расчёты, состояние — его меняют склад и сверка заказов
    ├── fulfillment/      партии печати, этапы комплектации, сверка заказов со складом
    ├── avito/            index.ts — связь с расширением Авито (extension/) и приём пачек заказов — заказы и настройки;
    │                     api.ts — клиент официального API Авито (через прокси дев-сервера Vite) — объявления
    ├── listings/         объявления Авито и их привязка к товарам (productId) — их читают объявления и склад
    ├── connections/      ключи Авито и Telegram — вносятся в настройках, читаются объявлениями
    ├── printer/          принтер XP-365B: настройки, генератор бирки, TSPL, WebUSB — его используют настройки и пульт

    └── styles/           tokens.css (цвета, отступы, скругления), global.css
```

## Правила

1. **Зависимости идут сверху вниз:** `app` → `features` → `shared`. `shared` ничего не знает о разделах; раздел не импортирует из другого раздела. Если что-то нужно двум разделам — оно переезжает в `shared`.
2. **Новый раздел** = папка в `features/` + одна строка в `app/routes.tsx`. Меню и роутинг строятся из этого списка сами.
3. **Внутри раздела** всё своё лежит рядом: страница, её компоненты, запросы к API, типы. Например, будущий склад: `features/stock/StockPage.tsx`, `StockTable.tsx`, `api.ts`, `types.ts`.
4. **Компонент = папка** с `.tsx` и `.module.css`. Стили не протекают между компонентами.
5. **Никаких цветов и отступов «на глаз»** — только переменные из `shared/styles/tokens.css`. Поменяли токен — поменялось везде.
6. **Импорты от корня** через `@/`: `import { Button } from "@/shared/ui"`.
7. **Статус всегда подписан текстом** (`StatusBadge`), цвет — подсказка, не единственный признак.

## Сервер и данные

С 25.11.2026 данные магазина — общие для кабинета и бота: **формат avito v1**, источник правды —
[`avito/data/schema/FORMAT.md`](../../data/schema/FORMAT.md). Читают и пишут их только через **сервер данных**
(`avito/data/server/server.mjs`, порт 8791, описание — `avito/data/server/README.md`); он проверяет каждую запись
(`avito/data/schema/validate.mjs`, не по формату — 422), хранит версии файлов (409 при конфликте), делает копии дня.
Своих данных у кабинета больше нет.

```
браузер ──/api/*──▶ server/server.mjs (8790) ──▶ сервер данных avito (DATA_URL, 8791) ──▶ store/*.json
         ──/avito/*──▶ server/server.mjs ──▶ api.avito.ru
бот ──────────────────────────────────────────▶ сервер данных avito
```

```
server/server.mjs       сервер кабинета: web/dist, /avito/* → api.avito.ru, /api/* → сервер данных (DATA_URL)
server/run-server.cmd   запуск на Windows: сначала поднимает сервер данных (если не запущен), потом хаб — порт 8790,
                        только 127.0.0.1, DATA_URL=http://127.0.0.1:8791, лог server/server.log
src/shared/lib/store.ts createFileStore — хранилище одного файла сервера данных
src/shared/lib/sync.ts  синхронизация файлов с сервером данных, подпись внизу меню
web/vite.config.ts      npm run dev: /api → DATA_URL (по умолчанию http://127.0.0.1:8791), /avito → api.avito.ru
web/api/state.ts        УСТАРЕЛО: функция старого прода на Vercel (Redis), кабинет туда больше не ходит
```

**`server/server.mjs`** (Node 20+, без зависимостей): отдаёт `web/dist`, проксирует `/avito/*` к Авито и `/api/*` —
к серверу данных как есть (любой метод, строка запроса, тело, заголовок `x-hubbro-key`; обратно — статус,
заголовки, тело). Сервер данных не отвечает — 502 `{ error: "Сервер данных не отвечает" }`. Переменные: `PORT`
(8790), `HOST` (127.0.0.1), `DATA_URL` (http://127.0.0.1:8791). **Ключ доступа проверяет сервер данных**
(его `ACCESS_KEY` / `ACCESS_KEY_FILE`), у сервера кабинета ключа больше нет.

- Где: `taylormomsen` (Windows, Tailscale), папка `C:\Users\kenya\claude_trusted\hub-bro\` (`server\`, `web\dist\`).
  Сервер данных (`avito\data\server\run-data.cmd`) поднимает `run-server.cmd` хаба или ярлык приложения менеджера —
  кто первый; его данные — `avito\data\store\`, ключ — `avito\data\server\access-key.txt` (тот же, что был у хаба).
  Задача `HubBroServer` запускает старый путь `claude_trusted\hub-bro\server\run-server.cmd`, он передаёт запуск сюда.
- Снаружи: `tailscale serve` → **https://taylormomsen.tailccfeb1.ts.net** — только внутри tailnet, с настоящим
  HTTPS (без него Chrome не даёт печатать по USB). Сам сервер слушает только `127.0.0.1:8790`.
- Обновить кабинет: `cd web && npm run build`, скопировать `web/dist` на сервер. Перезапуск не нужен.
- Локально: `PORT=8795 STORE=/tmp/store node ../data/server/server.mjs` (сервер данных) и
  `PORT=8796 DATA_URL=http://127.0.0.1:8795 node server/server.mjs`; для разработки — `npm run dev` в `web/`
  (сервер данных на 8791 или `DATA_URL=…`). Перевести старые данные кабинета (`hubbro.*.json`) —
  `node avito/data/schema/migrate-legacy.mjs --hub <папка> --bot <папка бота> --out <store>`.
- Старый прод на Vercel (`web/api/state.ts`, `web/vercel.json`, Upstash) больше не используется; файлы оставлены,
  `state.ts` помечен устаревшим и по-прежнему проверяется `npx tsc -b`.

**Что на сервере данных, что в браузере.** Хранилища кабинета = файлы формата v1. В браузере копия каждого лежит
под `hubbro.data.<файл>` (целиком, с чужими полями).

| Файл | Хранилище в кабинете | Что из него берёт кабинет |
|---|---|---|
| `catalog` | `catalogStore` (`shared/stock`) | шкала размеров, категории, товары. Поля бота (`match`, `botKey`, `description`, `sizeTable`, `sizeHW`, `photos`, `chart`, `availability`) и неизвестные поля переносятся как есть |
| `stock` | `stockFileStore` (`shared/stock`) | поставки (`productId`) и остатки `products[productId][size]` |
| `hub` | `hubStore` (`shared/stock`) | отображение склада, черновики поставок |
| `log` | `logStore` (`shared/stock`) | общая история (кабинет пишет `source: "hub"`, новые сверху, до 2000) |
| `orders` | `ordersStore` (`shared/orders`) | заказы (`productId` — связь с товаром) |
| `listings` | `listingsStore` (`shared/listings`) | объявления (`productId`), время обновления |
| `printBatches` | `batchesStore` (`shared/fulfillment`) | партии печати |
| `shop` | `serviceOrderStore` (`shared/fulfillment`) | только `serviceOrder`; название, `stockSource`, время отправки — бота, переносятся как есть |

Только в этом браузере: ключи Авито и Telegram `hubbro.connections.v2`, принтер `hubbro.printer.v3`,
`hubbro.printer.device.v2`, выбор «Что печатать» `hubbro.picking.queue.v4`, ключ доступа `hubbro.access.v1`.
Старые ключи `hubbro.<что-то>.vN` (в том числе прежние `hubbro.stock.v5`, `hubbro.orders.v3`, …) при запуске
удаляются (`shared/lib/cleanup.ts`).

**Склад = четыре файла.** Экраны работают с «моделью» (товар каталога + его поставки и остатки), как раньше:
`stockStore` (`shared/stock/store.ts`) склеивает `catalog` + `stock` + `hub` + `log` при чтении и разбирает обратно при
записи. Файл пишется, только если в нём что-то поменялось по сути (переименование не трогает `stock`, поставка — не
трогает `hub`). Подписчики склада узнают о правке один раз, когда все файлы на месте.

**Файловое хранилище** (`createFileStore`): проверяет `format` и `version` (чужая версия — не читаем и не пишем,
внизу меню ошибка), в памяти держит удобное кабинету состояние, на сервер отдаёт файл целиком: `format`, `version`,
поля кабинета и все поля, которых кабинет не знает (FORMAT.md, правило 7).

**Как работает синхронизация** (`startServerSync` в `main.tsx`, до сверки и экранов):
1. При открытии забираем все файлы с сервера данных и подставляем вместо браузерных (ждём не дольше 8 секунд).
   Файла ещё нет — сервер отдаёт пустой по формату (`rev: 0`), в браузере тоже пусто: **сервер главнее**.
2. Каждое изменение уходит на сервер через полсекунды тишины. Раз в 15 секунд (и при возврате на вкладку)
   спрашиваем версии и подтягиваем чужие правки (второй комп, бот).
3. **Сначала каталог:** остатки, заказы и объявления ссылаются на товары каталога, поэтому их отправка ждёт, пока
   уйдёт каталог (например, поставка нового товара: сначала `catalog`, потом `stock`).
4. **Старое не затирает новое:** отправляем вместе с версией, с которой взяли данные (`baseRev`). На сервере новее —
   409 с его данными. У `catalog`, `shop`, `log` (их пишет и бот) кабинет применяет свою правку заново поверх свежих
   данных (FORMAT.md, правило 8): трёхсторонняя склейка — поле поменяли только мы → наше, только они → их; списки с
   `id` (товары, категории, записи истории) склеиваются по элементам; оба поменяли одно поле — побеждает сервер.
   У остальных файлов (их пишет только кабинет) берём данные сервера, свою отправку выбрасываем — несколько секунд
   внизу меню «Данные обновились с другого компьютера». Одна отправка файла за раз.
5. **Не по формату (422):** сервер не принял файл — внизу меню красное «Сервер не принял данные» и ошибки проверки
   (`errors` из ответа). Сами не повторяем: ошибка висит, пока не поменяется что-то ещё или сервер не пришлёт новые
   данные. Пока висит, опрос её не прячет.
6. Пока файл не загрузился с сервера, он ничего туда не шлёт — пустой браузер не затрёт настоящие данные.
   Нет связи — внизу меню красное «Нет связи с сервером».
7. Сервера нет (локально, сервер данных не запущен) — прокси дев-сервера отвечает ошибкой без JSON, кабинет
   работает только в браузере, внизу меню «Данные в этом браузере».

**Ключ доступа:** задан у сервера данных — без заголовка `x-hubbro-key` он отвечает 401, кабинет один раз
спрашивает ключ и запоминает в браузере (`hubbro.access.v1`).

**Пустое название магазина:** пустой `shop.json` сервер отдаёт с `name: ""`, а записать его обратно не даст
(`validate.mjs`: название — непустая строка). Поэтому, если кабинет пишет `shop` (порядок служб) у магазина без
названия, он ставит название «Магазин».
