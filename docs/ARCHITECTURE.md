# HUB BRO — архитектура веб-кабинета

Стек: Vite + React 18 + TypeScript, react-router для разделов, CSS Modules для стилей. Код — в `web/`.

## Папки

```
web/src/
├── main.tsx              точка входа: роутер, глобальные стили
├── app/                  каркас приложения
│   ├── App.tsx           роуты
│   ├── routes.tsx        единый список разделов (путь, название, страница)
│   └── layout/           общий макет: боковое меню + рабочая область
├── features/             разделы, по папке на каждый
│   ├── labels/           Пульт (печать и расклейка партий)
│   ├── picking/          Комплектация
│   ├── stock/            Склад
│   ├── orders/           Заказы
│   ├── listings/         Объявления Авито и привязка к моделям склада
│   └── settings/         Настройки: Авито, Telegram, принтер, позже авторизация
└── shared/               то, что используется в нескольких разделах
    ├── orders/           заказы: типы, статусы, useOrders() — их читают заказы, комплектация, пульт
    ├── stock/            склад: типы, расчёты, состояние — его меняют склад и сверка заказов
    ├── fulfillment/      партии печати, этапы комплектации, сверка заказов со складом
    ├── avito/            index.ts — связь с расширением Авито (extension/) и приём пачек заказов — заказы и настройки;
    │                     api.ts — клиент официального API Авито (через прокси дев-сервера Vite) — объявления
    ├── listings/         объявления Авито и их привязка к моделям — их читают объявления и склад
    ├── connections/      ключи Авито и Telegram — вносятся в настройках, читаются объявлениями
    ├── printer/          принтер XP-365B: настройки, генератор бирки, TSPL, WebUSB — его используют настройки и пульт
    ├── lib/              общие мелочи: newId, createStore (общее состояние в localStorage), sync (синхронизация с сервером),
    │                     cleanup (удаление старых версий ключей при запуске)
    ├── ui/               базовые компоненты: Button, Card, Collapse, Input, PageHeader, StatusBadge
    └── styles/           tokens.css (цвета, отступы, скругления), global.css
```

## Правила

1. **Зависимости идут сверху вниз:** `app` → `features` → `shared`. `shared` ничего не знает о разделах; раздел не импортирует из другого раздела. Если что-то нужно двум разделам — оно переезжает в `shared`.
2. **Новый раздел** = папка в `features/` + одна строка в `app/routes.tsx`. Меню и роутинг строятся из этого списка сами.
3. **Внутри раздела** всё своё лежит рядом: страница, её компоненты, запросы к API, типы. Например, будущий склад: `features/stock/StockPage.tsx`, `StockTable.tsx`, `api.ts`, `types.ts`.
4. **Компонент = папка** с `.tsx` и `.module.css`. Стили не протекают между компонентами.
5. **Никаких цветов и отступов «на глаз»** — только переменные из `shared/styles/tokens.css`. Поменяли токен — поменялось везде.
6. **Импорты от корня** через `@/`: `import { Button } from "@/shared/ui"`.
7. **Статус всегда подписан текстом** (`StatusBadge`), цвет — подсказка, не единственный признак.

## Сервер (Vercel)

Кабинет выложен на Vercel: **https://hub-bro.vercel.app** (выложен 18.11.2026). Проект `hub-bro` с корнем `web/`,
каждый пуш в `main` выкатывается сам. HTTPS там из коробки — без него Chrome не даёт печатать по USB.

```
web/api/state.ts        функция Vercel: GET/PUT /api/state — JSON по ключу в Redis (Upstash из маркетплейса Vercel)
web/api/tsconfig.json   типы для функций (Node) — отдельно от кабинета, npx tsc -b проверяет оба
web/vercel.json         /avito/* → api.avito.ru (вместо прокси дев-сервера), остальное → index.html
src/shared/lib/sync.ts  синхронизация хранилищ с сервером, подпись внизу меню
```

**Проект в Vercel:** Root Directory `web`, пресет Vite (из `vercel.json`), сборка и вывод по умолчанию
(`npm run build` → `dist`). Переменные окружения (Production и Preview):

| Переменная | Откуда | Зачем |
|---|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | интеграция Upstash for Redis (Storage → Upstash, план Free, Frankfurt), префикс `KV` | адрес и токен базы; `state.ts` берёт их или `UPSTASH_REDIS_REST_*` |
| `ACCESS_KEY` | задаём сами, длинная случайная строка, Sensitive | ключ доступа к `/api/state` (ниже) |

Новая переменная доходит до сайта только после нового деплоя (Deployments → Redeploy).

**Что на сервере, что в браузере:**

| На сервере (общее для всех) | Только в этом браузере |
|---|---|
| заказы `hubbro.orders.v3`, склад `hubbro.stock.v5`, партии `hubbro.batches.v2`, объявления `hubbro.listings.v2`, порядок служб в очереди печати `hubbro.picking.services.v2` | ключи Авито и Telegram `hubbro.connections.v2` (секреты не отдаём открытой ссылке), настройки и выбранный принтер `hubbro.printer.v3`, `hubbro.printer.device.v2` (у каждого компа свой), выбор «Что печатать» в комплектации `hubbro.picking.queue.v4`, ключ доступа `hubbro.access.v1` |

**Чистый старт (18.11.2026):** тестовых данных в коде нет — без сохранённого всё пусто. Версии всех ключей подняты,
старые (`orders.v2`, `stock.v4`, `connections.v1` и т. д.) не читаются, а при запуске удаляются из браузера
(`shared/lib/cleanup.ts`) — ничего с localhost или от прежних версий на сервер не попадёт. Очистить всё —
Настройки → «Данные» (SETTINGS.md, 5а): общие хранилища сбрасываются на пустые и сразу уходят на сервер
(`flushServerSync`), браузерные ключи удаляются.

**Как работает синхронизация** (`startServerSync` в `main.tsx`, до сверки и экранов):
1. При открытии забираем хранилища с сервера и подставляем вместо браузерных (ждём не дольше 8 секунд) —
   на новом компе сразу настоящие данные, а не пустой кабинет.
2. **Сервер главнее:** на сервере пусто — в браузере тоже пусто (хранилище сбрасывается). Данные из браузера на
   сервер сами не переезжают. Дальше правки уходят на сервер.
3. Каждое изменение уходит на сервер через полсекунды тишины. Раз в 15 секунд (и при возврате на вкладку)
   спрашиваем версии и подтягиваем чужие правки.
4. **Старое не затирает новое.** У каждого хранилища на сервере номер версии (`hubbro:revs`) и время сохранения
   (`hubbro:saved`, по часам сервера — часы компов могут расходиться, поэтому сравниваем не время, а версию).
   Кабинет отправляет данные вместе с версией, с которой их взял (`baseRev`). Если на сервере уже версия новее
   (кто-то сохранил позже), сервер ничего не пишет и отвечает 409 со своими данными. Кабинет берёт их, а свою
   отправку выбрасывает. Проверка и запись идут одним Lua-скриптом в Redis, поэтому два компа не проскочат
   одновременно. То же при опросе: на сервере версия новее, а у нас правка ждёт отправки — берём данные сервера,
   правку выбрасываем (она сделана поверх старых данных, сервер её всё равно не примет). Запрос без `baseRev`
   (вкладка, открытая до обновления кабинета) сервер не пишет. Цена: если двое правят одно хранилище в одни и
   те же секунды, правка второго не сохранится и её надо повторить. С настоящим бэкендом — правки по отдельным заказам.
   Одна отправка хранилища за раз: правки во время отправки уходят следующей, с новой версией.
   Внизу меню — «Сохранено на сервере в 14:32» (самое позднее сохранение среди хранилищ), а после отказа
   несколько секунд «Данные обновились с другого компьютера».
5. Пока хранилище не загрузилось с сервера, оно ничего туда не шлёт — пустой браузер не затрёт настоящие данные.
   Нет связи — внизу меню красное «Нет связи с сервером», правки в это время остаются только в браузере и
   пропадут, когда связь вернётся (сервер главнее).
6. Сервера нет (локально без `HUBBRO_API`) — дев-сервер отвечает на `/api` 404, кабинет работает только в
   браузере, внизу меню «Данные в этом браузере».

**Ключ доступа** (пока нет авторизации): переменная окружения `ACCESS_KEY` в проекте Vercel. Задана — без
заголовка `x-hubbro-key` сервер отвечает 401, кабинет один раз спрашивает ключ и запоминает в браузере.
Не задана — данные открыты всем, у кого есть ссылка.

**Локально с данными сервера:** `HUBBRO_API=https://hub-bro.vercel.app npm run dev` — дев-сервер прокидывает
`/api` на Vercel.

**Запас бесплатного Upstash** — 256 МБ и 500 тыс. команд в месяц; открытая вкладка тратит ~1 команду в 15 секунд
(около 60 тыс. в месяц при работе 8 часов в день), плюс 1 на каждое сохранение (Lua-скрипт) и по 3 на каждую
загрузку хранилища или отказ (данные, версия, время).

**Лимит размера:** хранилище уходит на сервер целиком одним запросом, а Vercel принимает тело не больше 4,5 МБ.
Это тысячи заказов с историей — сейчас далеко; упрёмся — делить заказы по ключам или правки по отдельным заказам.
