# Комплектация и пульт — полная документация

Единственный источник правды по комплектации и пульту HUB BRO: как заказ встаёт в резерв, что такое очередь
печати и партия, какие правила нельзя нарушать, как считаются цифры, как работают оба экрана.

**Как пользоваться документом:**
- перед любой работой с комплектацией и пультом (`web/src/features/picking/`, `web/src/features/labels/`,
  `web/src/shared/fulfillment/`) читай его, а также [ORDERS.md](ORDERS.md) и [WAREHOUSE.md](WAREHOUSE.md) там,
  где комплектация читает или меняет заказы и склад;
- после любого изменения (логика, данные, экраны, тексты) обнови нужные разделы и журнал изменений внизу
  в том же коммите;
- задело заказы или склад — обнови и их документы.

Код: экран комплектации — `web/src/features/picking/`, экран пульта — `web/src/features/labels/` (путь `/labels`,
папка осталась от «Расклейки»), общее для обоих — `web/src/shared/fulfillment/`: партии, этапы, сверка со складом.
Бэкенда нет: данные тестовые и живут в браузере (раздел 9).

**Внешний вид и поведение экранов, описанные здесь, утверждены** (14.11.2026). Менять — только по договорённости.

## 1. Словарь

| Термин | Что это |
|---|---|
| **Комплектация** | Экран, где заказы со склада выстраиваются в очередь печати и уходят партиями на пульт. |
| **Пульт** | Экран, где партию печатают и отмечают «Партия расклеена». Бывшая «Расклейка». |
| **Сверка** | Автоматическое сопоставление заказов со складом: резерв, снятие резерва, пометки проблем. |
| **Резерв** | Джинса на складе, закреплённая за заказом (`Unit` со статусом `reserve`). Берётся из самой старой поставки. |
| **Проблема** | Пометка на заказе в «Заказан»: «Без размера» или «Нет на складе». Такой заказ в очередь не идёт. |
| **Очередь печати** | Заказы в «Заказан» без проблем (с резервом), которые ещё не в партии на пульте. |
| **Уровень сортировки** | Признак, по которому выстраивается очередь: категория, модель, размер, служба доставки. |
| **Пресет** | Готовый набор уровней: «По размерам», «Под упаковку по службам», «По моделям». |
| **Группа** | Подряд идущие заказы очереди с одинаковыми значениями всех включённых уровней: «Джинсы Клёш · 30S». |
| **Партия печати** | Заказы, которые комплектация одним действием отправила на пульт. Номер №1, №2… Не путать с поставкой склада. |
| **Ошибка расклейки** | Бирка из партии, которую не смогли наклеить: не напечаталась, штрихкод не читается, испорчена, другое. |
| **Этап** | Где заказ в комплектации: Проблема, К печати, В партии, Напечатан, Собран. Не статус — считается. |
| **Служба доставки** | СДЭК, Авито, Почта, Яндекс, 5Post. Адреса ПВЗ нет, только служба. |

## 2. Как проходит заказ

```
 заказ «Заказан» ──► СВЕРКА со складом
                       ├─ нет размера            → ⚠ Без размера   ─┐
                       ├─ размер есть, джинсы нет → ⚠ Нет на складе ─┤ список «Проблемы» в комплектации
                       └─ размер есть, джинса есть → резерв (−1 на полке)
                                                      │
                                              ОЧЕРЕДЬ ПЕЧАТИ (К печати)
                                                      │  комплектация: «В партию» / «На пульт»
                                              ПАРТИЯ на пульте (В партии)
                                                      │  пульт: «Напечатать»
                                              Напечатана (Напечатан)
                                                      │  пульт: «Партия расклеена»
                                ┌─────────────────────┴─────────────────────┐
                        бирка без ошибки                             бирка с ошибкой
                        статус «Собран»                       снова в очереди (К печати)
```

- Проблема снимается сама: пришёл размер — заказ идёт на склад; пришла поставка — заказ встаёт в резерв.
- «Вернуть в очередь» на пульте (до расклейки) возвращает все заказы партии в очередь.
- Авито отменил заказ — сверка снимает резерв, джинса на полку; заказ пропадает из очереди. Если он уже был в
  партии, на пульте у него серый бейдж «Отменён», и «Собран» он не получит.

## 3. Что хранится

Типы — `shared/fulfillment/types.ts`. Заказ и джинса со склада описаны в [ORDERS.md](ORDERS.md) и
[WAREHOUSE.md](WAREHOUSE.md); комплектация пользуется у заказа полями `status`, `problem`, `size`, `product`,
`service`, `chatId`, `createdAt`, у склада — `Model.sizes[].stock` и `units`.

### Партия печати (`PrintBatch`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | string | Внутренний id |
| `number` | number | №1, №2… — следующий после самого большого номера |
| `createdAt` | ISO | Когда отправили из комплектации |
| `orderIds` | string[] | Номера заказов **в порядке очереди** — это и есть порядок печати |
| `note` | string | Как собирали: «Категория → Модель → Размер · только Джинсы Клёш, СДЭК» |
| `printedAt?` | ISO | Отметка «Напечатать» (принтера пока нет) |
| `stuckAt?` | ISO | Нажали «Партия расклеена» |
| `cancelledAt?` | ISO | Вернули в очередь, не расклеив |
| `issues` | `BatchIssue[]` | Бирки с ошибкой. Пусто — всё расклеено |

### Ошибка расклейки (`BatchIssue`)

`{ orderId, reason, comment? }`. Причины (`IssueReason`): `notPrinted` Бирка не напечаталась · `badCode` Штрихкод
не читается · `damaged` Бирка испорчена · `other` Другое. Комментарий — по желанию.

### Состояние партии (`BatchState`) — считается, не хранится

| Состояние | Когда | Бейдж |
|---|---|---|
| `queued` Ждёт печати | нет ни одной отметки | жёлтый |
| `printed` Напечатана | есть `printedAt` | жёлтый |
| `stuck` Расклеена | есть `stuckAt` | зелёный |
| `cancelled` Возвращена в очередь | есть `cancelledAt` | серый |

Партия **на пульте** (`isActive`) — не расклеена и не возвращена.

### Этап заказа (`Stage`) — считается, не хранится

`orderStage(заказ, партии)` в `shared/fulfillment/batches.ts`:

| Этап | Условие | Тон |
|---|---|---|
| — | статус не «Заказан» и не «Собран» (отправлен, отменён и дальше) — заказ уже не наш | — |
| Собран | статус «Собран» | зелёный |
| Проблема | «Заказан» + есть `problem` | красный |
| В партии | «Заказан» + в партии на пульте без `printedAt` | жёлтый |
| Напечатан | «Заказан» + в партии на пульте с `printedAt` | жёлтый |
| К печати | «Заказан», без проблемы, не в партии на пульте | жёлтый |

### Настройка очереди (`QueueConfig`)

`{ levels, models, sizes, services }`:
- `levels` — все четыре уровня в нужном порядке, у каждого `on` (включён ли);
- `models`, `sizes`, `services` — фильтры. Пусто — все.

## 4. Правила (не нарушать)

1. **Этапы — не статусы.** «К печати», «В партии», «Напечатан» считаются из статуса, пометки и партий. Новых статусов
   заказа под них не заводим (ORDERS.md, правило 13).
2. **Сверка автоматическая.** Резерв, снятие резерва и пометки ставит только сверка, руками — никогда. Повторный
   запуск ничего не меняет.
3. **Резерв — из самой старой поставки** (по дате), как требует склад (WAREHOUSE.md, правило 6).
4. **Кто раньше заказал, тому и джинса.** Сверка обходит заказы от старых к новым.
5. **Заказ с проблемой в очередь не идёт** и не печатается.
6. **Заказ в партии на пульте в очереди не показывается** — второй раз его в партию не отправить.
7. **Партия уходит в порядке очереди,** а не в порядке кликов по галочкам.
8. **«Собран» ставит только «Партия расклеена»** — и только заказам без ошибки, которые всё ещё «Заказан», без
   проблемы и с резервом (ORDERS.md, правила 9 и 14).
9. **Заказ с ошибкой расклейки остаётся «Заказан»** и снова попадает в очередь.
10. **Вернуть в очередь можно только нерасклеенную партию.**
11. **Партии не удаляются.** Возврат в очередь и расклейка ставят отметку, партия остаётся в истории пульта.
12. **Расклеенная партия больше не меняется.**
13. **Экраны статусы Авито не трогают:** комплектация только собирает партии, пульт ставит только «Собран».

## 5. Сверка со складом

`syncReserves(заказы, модели)` в `shared/fulfillment/reserve.ts` — чистая функция: возвращает новые заказы и модели
или `null`, если менять нечего.

Заказы обходятся от старых к новым (`createdAt`):

| Заказ | Что делает сверка | На полке |
|---|---|---|
| «Заказан» без размера | пометка «Без размера» | 0 |
| «Заказан» / «Собран» с размером, резерв уже есть | снимает пометку | 0 |
| «Заказан» / «Собран» с размером, резерва нет, джинса есть | резерв: джинса из самой старой поставки, `Unit { order, orderDate ДД.ММ, status: reserve, batchId }`, пометка снимается | −1 |
| «Заказан» с размером, джинсы нет | пометка «Нет на складе» | 0 |
| «Отменён» с резервом | резерв снят, джинса на полку **своей** поставки, пометка снимается | +1 |
| Остальные статусы | не трогает | 0 |

- Модель ищется по названию (`Order.product` = `Model.name`), размер — по подписи.
- Записи `stock` с нулём удаляются (как требует склад).
- **Когда запускается** (`startReserveSync` в `shared/fulfillment/store.ts`, вызывается в `main.tsx`): при старте
  приложения и после каждого изменения заказов или склада — на любом экране. Добавил поставку на складе —
  заказы с «Нет на складе» сразу встают в резерв.
- Пока не делает: статус джинсы после отправки (`sent`, `delivered`) и возвраты из заказа не выводятся.

## 6. Как считаются цифры

`features/picking/queue.ts`, `shared/fulfillment/batches.ts`.

### Комплектация

- **Очередь** `buildQueue` — заказы с этапом «К печати». Для каждого запоминаются позиции для сортировки.
- **Всего** — заказы с этапом Проблема, К печати, В партии или Напечатан. Под цифрой: «к печати N · в партиях M ·
  проблем K» (в партиях = В партии + Напечатан).
- **На печать** — вся очередь, без фильтров.
- **Товаров** — сколько разных моделей в очереди. Под цифрой — «модель количество» через « · » в порядке склада.
- **ПВЗ** — сколько разных служб в очереди. Под цифрой — все службы с количеством, нули тоже.
- **Проблемы** — заказы с этапом «Проблема».
- **Отпечатано сегодня** — партии (кроме возвращённых) с `printedAt` сегодня (местный день) и сумма штук в них.
- **Счётчики на чипах фильтров** — по всей очереди без фильтров. Размеры считаются в пределах выбранных моделей.
- **Счётчик «Очередь печати N»** — после фильтров.

### Порядок очереди

`sortQueue`: по включённым уровням по очереди, при равенстве — кто раньше заказал (`createdAt`).

| Уровень | Порядок |
|---|---|
| Категория | как категории в настройках склада; модели без категории — в конце |
| Модель | как модели на складе (порядок массива моделей) |
| Размер | как размеры у своей модели (настраивается на складе) |
| Служба доставки | СДЭК → Авито → Почта → Яндекс → 5Post |

Пресеты (`PRESETS`), включённые уровни — в этом порядке, остальные выключены и стоят ниже:

| Пресет | Уровни |
|---|---|
| **По размерам** (по умолчанию) | Категория → Модель → Размер |
| **Под упаковку по службам** | Служба доставки → Категория → Модель → Размер |
| **По моделям** | Категория → Модель |

Пресет подсвечен, пока уровни (порядок и включённость) совпадают с ним в точности. Поменял руками — подсветка
пропадает.

### Группы

`groupQueue`: подряд идущие заказы с одинаковыми значениями **всех включённых** уровней — одна группа.
Заголовок — значения через « · ». Категория в заголовке не пишется, если включена модель («Джинсы Клёш · 30S», а не
«Джинсы · Джинсы Клёш · 30S»). Ни одного уровня не включено — одна группа «Все заказы».

### Фильтры

`filterQueue`: модель, размер и служба — каждый пустой список значит «все», выбранные значения складываются через
«или» внутри фильтра и через «и» между фильтрами.
- Чипы моделей — только модели, которые есть в очереди, в порядке склада.
- Чипы размеров — размеры выбранных моделей (или всех моделей очереди), которые есть в очереди. Одна модель —
  её порядок размеров, несколько — общий `compareSizes` (буквенные S, M, L… раньше числовых). Чипы размеров
  показываются, только если размеров больше одного.
- Чипы служб — все четыре всегда, с нулями.
- Смена модели (и «Все модели») сбрасывает выбранные размеры.

### Подпись партии

`describeConfig`: включённые уровни через « → » (нет ни одного — «по времени заказа»), и если есть фильтры —
« · только » и все выбранные модели, размеры и службы через запятую.

### Пульт

- **Ждут печати** / **Ждут расклейки** — партии в состоянии Ждёт печати / Напечатана и сумма штук.
- **Расклеено сегодня** — партии с `stuckAt` сегодня; штук собрано = штук в них минус ошибки.
- **Ошибок сегодня** — сумма ошибок в партиях, расклеенных сегодня.
- В карточке: состав — «модель размер ×N» в порядке первого появления в партии; службы — «служба ×N»;
  «собрано N» при подтверждении — заказы партии, которые сейчас «Заказан» и без отмеченной ошибки.

## 7. Экран «Комплектация»

`features/picking/PickingPage.tsx`, путь `/picking`, первый пункт меню. Сверху вниз:

1. **Шапка:** «Комплектация», подпись «Заказы со склада → очередь печати → партия на пульт».
2. **Плитки** (`shared/ui/StatTiles`) в сетке, сколько влезает в ряд (от 150 px):
   Всего · На печать · Товаров · ПВЗ · Проблемы · Отпечатано сегодня (раздел 6). Под каждой цифрой мелкая строка.
   - «Проблемы» с красной подложкой, пока есть хоть одна, подпись «показать список ↓»; клик раскрывает список
     проблем и плавно прокручивает к нему. Проблем нет — серая, «всё чисто», не кликается.
3. **«⚠ Показать проблемы N»** (`ProblemList/`) — красная плашка со стрелкой, клик раскрывает на месте (`Collapse`),
   надпись меняется на «Скрыть проблемы». Нет проблем — плашки нет.
   Строка (на бежевом): товар и размер чёрным чипом (нет размера — чипа нет), `№ номер · служба · чат ↗` (ссылка на чат,
   если есть), подсказка «→ …» красным и справа бейдж «⚠ Без размера» / «⚠ Нет на складе». На телефоне бейдж
   уходит под текст. У «Без размера» под подсказкой — чипы размеров модели со склада с остатком на полке: клик
   ставит размер (пока нет бота Гришки), сверка тут же ставит резерв или «Нет на складе».
   Подсказка (`problems.ts`), первая подходящая:
   - модели нет на складе → «Модели «…» нет на складе — заведите её в настройках склада»;
   - «Без размера» → «Выберите размер из чата с покупателем»;
   - у этого размера есть возврат на разбор → «Есть возврат на разбор: заказ №… — разберите его на полку»;
   - у этого размера едет возврат → «Едет возврат: заказ №… — дождитесь или докупите 33M»;
   - иначе → «Докупить: Джинсы Клёш, 34L».
4. **«Очередь печати N»** и панель настройки (`QueueSettings/`) — карточка в две колонки, на узком экране (≤ 860 px)
   в одну:
   - слева **«Порядок печати»**: чипы трёх пресетов и список четырёх уровней. У уровня галочка (выключенный
     бледнее) и кнопки ↑ / ↓ (у крайних неактивны);
   - справа **«Что печатать»**: ряд чипов моделей («Все модели» + модели со счётчиком), ряд размеров («Все размеры»
     + размеры), ряд служб («Все службы» + четыре службы). Можно выбрать несколько в каждом ряду.
5. **Группы очереди** (`QueueGroupCard/`) — карточка на группу:
   - заголовок: галочка «выбрать всю группу» (частично выбрана — промежуточное состояние), название, количество,
     справа чёрная кнопка **«В партию →»** — сразу отправляет всю группу на пульт;
   - строки: галочка, размер чёрным чипом, товар, ниже `№ 4 812 336 580 · 08:12 · Авито`.
     Время у сегодняшних заказов, у остальных — «13.11, 11:44». Клик по строке ставит / снимает галочку.
   - пусто: «Под фильтр ничего не попало» или «Очередь пуста — всё отправлено на пульт».
6. **Панель действий** — прилипает к низу экрана, пока листаешь очередь (только если в очереди после фильтров
   что-то есть):
   - слева «В очереди N» или «Выбрано N из M» (считаются только выбранные среди видимых);
   - «Снять выбор» — если что-то выбрано;
   - **«Всё на пульт (N)»** — всё видимое после фильтров, или **«Выбранные на пульт (N)»**.
   После отправки выбор с отправленных снимается, по центру над панелью на 4 секунды всплывает чёрное
   «Партия №N на пульте: K шт. · На пульт →».
7. **«Партии сегодня»** — если сегодня собирали партии: справа ссылка «открыть пульт →», список строк
   «№N · время · штук · подпись · бейдж состояния».

Настройка очереди запоминается в этом браузере (раздел 9). Выбор галочками не запоминается.

## 8. Экран «Пульт»

`features/labels/LabelsPage.tsx`, путь `/labels`, пункт меню «Пульт». Сверху вниз:

1. **Шапка:** «Пульт», подпись «Печать и расклейка партий из комплектации. Принтер подключим позже».
2. **Плитки:** Ждут печати · Ждут расклейки · Расклеено сегодня · Ошибок сегодня (красная, если есть) (раздел 6).
3. **«На пульте»** — партии на пульте, **старые сверху** (по номеру), чтобы печатать по порядку.
   Нет — «Партий нет. Собери партию в комплектации» со ссылкой.
4. **Карточка партии** (`BatchCard/`):
   - шапка: «Партия №N», `время · N шт.`, справа бейдж состояния;
   - подпись (как собирали), состав «Джинсы Клёш 30S ×2» жирнее, службы «СДЭК ×1 · Авито ×1»;
   - «Показать заказы ▾» раскрывает список (`Collapse`): размер чёрным чипом, товар, `№ номер · служба`; заказ уже не
     «Заказан» и не «Собран» — серый бейдж статуса; заказ с ошибкой — красная строка, бейдж «⚠ причина»,
     комментарий под ним; заказа нет в данных — «Заказ не найден».
   - **Ждёт печати:** **«Напечатать»** (пока просто ставит отметку) и **«Вернуть в очередь»** → прямо в карточке
     «Вернуть N шт. в очередь комплектации?» **«Да, вернуть»** / «Нет».
   - **Напечатана:** **«Партия расклеена»** → список заказов раскрывается, у каждого выбор «Расклеена» или
     «⚠ причина»; выбрал причину — появляется поле «Комментарий». Подсказка «Отметь бирки с ошибкой — эти заказы
     вернутся в очередь», кнопки **«Подтвердить: собрано N, в очередь M»** (без ошибок — просто «собрано N») и
     «Отмена».
   - **Расклеена / возвращена:** карточка серая, строка итога «Расклеена в 12:30 · собрано N · вернули в очередь M»
     или «Вернули в очередь в 12:30». Кнопок нет.
5. **«Показать историю N ▾»** — расклеенные и возвращённые партии, свежие сверху, раскрывается на месте.

## 9. Хранение

Общее состояние — `shared/lib/store.ts` (`createStore`): одно на все экраны, хранится в `localStorage`, экраны
подписаны и обновляются сами.

| Что | Ключ | Где |
|---|---|---|
| Партии печати | **`hubbro.batches.v1`** | `shared/fulfillment/store.ts` |
| Заказы (статусы, пометки) | `hubbro.orders.v1` | `shared/orders/index.ts`, см. ORDERS.md |
| Склад (резервы) | `hubbro.stock.v4` | `shared/stock/store.ts`, см. WAREHOUSE.md |
| Настройка очереди | `hubbro.picking.queue.v1` | `features/picking/PickingPage.tsx` — удобство одного браузера |

- Пусто или повреждено → тестовые данные (партий нет, очередь по умолчанию «По размерам»).
- Сбросить всё — удалить ключи (или очистить localStorage сайта).
- Если меняется формат — поднять версию ключа.
- Когда появится бэкенд, меняются только `store.ts`; логика (`reserve.ts`, `batches.ts`, `queue.ts`) остаётся.

**Действия** (`shared/fulfillment/store.ts`):

| Действие | Кто вызывает | Что делает |
|---|---|---|
| `createBatch(orderIds, note)` | комплектация | новая партия с номером max+1 |
| `markPrinted(id)` | пульт, «Напечатать» | `printedAt` |
| `cancelBatch(id)` | пульт, «Вернуть в очередь» | `cancelledAt` |
| `markStuck(id, issues)` | пульт, «Партия расклеена» | заказам без ошибки (Заказан, без проблемы, с резервом) — запись «Собран» в историю; партии — `stuckAt`, `issues`, `printedAt` если не было. Повторно не срабатывает |
| `startReserveSync()` | `main.tsx`, один раз | сверка сразу и после каждого изменения заказов или склада |

Тестовые данные, на которых видно всё: 18 заказов в «Заказан» — 13 в очереди на трёх моделях и всех четырёх службах,
2 «Без размера» и 3 «Нет на складе» с тремя разными подсказками (докупить, возврат на разбор, едет возврат).
