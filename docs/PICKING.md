# Комплектация и пульт — полная документация

Единственный источник правды по комплектации и пульту HUB BRO: как заказ встаёт в резерв, что такое очередь
печати и партия, какие правила нельзя нарушать, как считаются цифры, как работают оба экрана.

**Как пользоваться документом:**
- перед любой работой с комплектацией и пультом (`web/src/features/picking/`, `web/src/features/labels/`,
  `web/src/shared/fulfillment/`) читай его, а также [ORDERS.md](ORDERS.md) и [WAREHOUSE.md](WAREHOUSE.md) там,
  где комплектация читает или меняет заказы и склад;
- после любого изменения (логика, данные, экраны, тексты) обнови нужные разделы и журнал изменений внизу
  в том же коммите;
- задело заказы или склад — обнови и их документы.

Код: экран комплектации — `web/src/features/picking/`, экран пульта — `web/src/features/labels/` (путь `/labels`,
папка осталась от «Расклейки»), общее для обоих — `web/src/shared/fulfillment/`: партии, этапы, сверка со складом,
очередь печати и выбор «Что печатать».
Данные — на сервере данных avito (общий формат [avito/data/schema/FORMAT.md](../../data/schema/FORMAT.md)) с копией в браузере (раздел 9).

**Внешний вид и поведение экранов, описанные здесь, утверждены** (14.11.2026). Менять — только по договорённости.

## 1. Словарь

| Термин | Что это |
|---|---|
| **Комплектация** | Экран, где заказы со склада выстраиваются в очередь печати и уходят партиями на пульт. |
| **Пульт** | Экран, где партию печатают и отмечают «Партия расклеена». Бывшая «Расклейка». Партию можно собрать и прямо здесь — быстрой печатью. |
| **Быстрая печать** | Блок на пульте: выбрал, что печатать, посмотрел состав, подтвердил — партия на пульте, без захода в комплектацию. |
| **Выбор «Что печатать»** | Общий для комплектации и быстрой печати: «Все» / по товару (и его размерам) / по службе. |
| **Сверка** | Автоматическое сопоставление заказов со складом: резерв, снятие резерва, пометки проблем. |
| **Резерв** | Джинса на складе, закреплённая за заказом (`Unit` со статусом `reserve`). Берётся из самой старой поставки. |
| **Проблема** | Пометка на заказе в «Заказан»: «Товар не выбран», «Без размера» или «Нет на складе». Такой заказ в очередь не идёт. |
| **Очередь печати** | Заказы в «Заказан» без проблем (с резервом), которые ещё не в партии на пульте. |
| **Порядок очереди** | Один, автоматический: Категория → Товар → Размер → Служба доставки, внутри — срочные первыми. Меняется только порядок служб. |
| **Группа** | Подряд идущие заказы очереди с одним товаром, размером и службой — одна стопка на расклейке: «Джинсы Клёш · 30S · СДЭК». |
| **Партия печати** | Заказы, которые комплектация или быстрая печать одним действием отправили на пульт. Номер №1, №2… Не путать с поставкой склада. |
| **Ошибка расклейки** | Бирка из партии, которую не смогли наклеить: не напечаталась, штрихкод не читается, испорчена, другое. |
| **Этап** | Где заказ в комплектации: Проблема, К печати, В партии, Напечатан, Собран. Не статус — считается. |
| **Служба доставки** | СДЭК, Авито, Почта, Яндекс, 5Post, DPD. Адреса ПВЗ нет, только служба. |

## 2. Как проходит заказ

```
 заказ «Заказан» ──► СВЕРКА со складом
                       ├─ нет размера            → ⚠ Без размера   ─┐
                       ├─ размер есть, джинсы нет → ⚠ Нет на складе ─┤ список «Проблемы» в комплектации
                       └─ размер есть, джинса есть → резерв (−1 на полке)
                                                      │
                                              ОЧЕРЕДЬ ПЕЧАТИ (К печати)
                                                      │  комплектация: «В партию» / «На пульт»
                                                      │  или пульт: быстрая печать → «Создать партию»
                                              ПАРТИЯ на пульте (В партии)
                                                      │  пульт: «Напечатать»
                                              Напечатана (Напечатан)
                                                      │  пульт: «Партия расклеена»
                                ┌─────────────────────┴─────────────────────┐
                        бирка без ошибки                             бирка с ошибкой
                        статус «Собран»                       снова в очереди (К печати)
```

- Проблема снимается сама: пришёл размер — заказ идёт на склад; пришла поставка — заказ встаёт в резерв.
- «Вернуть в очередь» на пульте (до расклейки) возвращает все заказы партии в очередь.
- Авито отменил заказ — сверка снимает резерв, джинса на полку; заказ пропадает из очереди. Если он уже был в
  партии, на пульте у него серый бейдж «Отменён», и «Собран» он не получит.

## 3. Что хранится

Типы — `shared/fulfillment/types.ts`. Заказ и джинса со склада описаны в [ORDERS.md](ORDERS.md) и
[WAREHOUSE.md](WAREHOUSE.md); комплектация пользуется у заказа полями `status`, `problem`, `size`, `product`,
`service`, `shipBy`, `chatId`, `createdAt`, у склада — `Model.sizes[].stock` и `units`.

### Партия печати (`PrintBatch`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | string | Внутренний id |
| `number` | number | №1, №2… — следующий после самого большого номера |
| `createdAt` | ISO | Когда отправили из комплектации или собрали быстрой печатью |
| `orderIds` | string[] | Номера заказов **в порядке очереди** — это и есть порядок печати |
| `note` | string | Как собирали: «Категория → Товар → Размер → Служба · только Джинсы Клёш (30S, 31M), СДЭК» |
| `printedAt?` | ISO | Когда принтер принял бирки партии. Ставится только после успешной отправки |
| `reprints?` | `Reprint[]` | Перепечатки до расклейки, по порядку: `{ at, orderId? }`, без `orderId` — вся партия |
| `stuckAt?` | ISO | Нажали «Партия расклеена» |
| `cancelledAt?` | ISO | Вернули в очередь, не расклеив |
| `issues` | `BatchIssue[]` | Бирки с ошибкой. Пусто — всё расклеено |

### Ошибка расклейки (`BatchIssue`)

`{ orderId, reason, comment? }`. Причины (`IssueReason`): `notPrinted` Бирка не напечаталась · `badCode` Штрихкод
не читается · `damaged` Бирка испорчена · `other` Другое. Комментарий — по желанию.

### Состояние партии (`BatchState`) — считается, не хранится

| Состояние | Когда | Бейдж |
|---|---|---|
| `queued` Ждёт печати | нет ни одной отметки | жёлтый |
| `printed` Напечатана | есть `printedAt` | жёлтый |
| `stuck` Расклеена | есть `stuckAt` | зелёный |
| `cancelled` Возвращена в очередь | есть `cancelledAt` | серый |

Партия **на пульте** (`isActive`) — не расклеена и не возвращена.

### Этап заказа (`Stage`) — считается, не хранится

`orderStage(заказ, партии)` в `shared/fulfillment/batches.ts`:

| Этап | Условие | Тон |
|---|---|---|
| — | статус не «Заказан» и не «Собран» (отправлен, отменён и дальше) — заказ уже не наш | — |
| Собран | статус «Собран» | зелёный |
| Проблема | «Заказан» + есть `problem` | красный |
| В партии | «Заказан» + в партии на пульте без `printedAt` | жёлтый |
| Напечатан | «Заказан» + в партии на пульте с `printedAt` | жёлтый |
| К печати | «Заказан», без проблемы, не в партии на пульте | жёлтый |

### Выбор «Что печатать» (`QueueSelection`)

`{ products, services }` в `shared/fulfillment/queue.ts`. Порядка в нём нет: он всегда один.

| Поле | Тип | Что это |
|---|---|---|
| `products` | `Record<товар, размеры[] \| null> \| null` | `null` — все товары. Иначе — только отмеченные товары; у товара `null` — все его размеры, список — только эти размеры |
| `services` | `DeliveryService[] \| null` | `null` — все службы. Иначе — только отмеченные |

«Все» — `{ products: null, services: null }` (`ALL_SELECTED`).

### Порядок служб

Список служб доставки (`DeliveryService[]`) в том порядке, в каком раскладываются стопки. По умолчанию
**Яндекс → Авито → СДЭК → Почта → 5Post → DPD**. Общий для всех компов. Код — `shared/fulfillment/serviceOrder.ts`;
сохранённый список чистится: неизвестные службы выкидываются, недостающие дописываются в конец.

## 4. Правила (не нарушать)

1. **Этапы — не статусы.** «К печати», «В партии», «Напечатан» считаются из статуса, пометки и партий. Новых статусов
   заказа под них не заводим (ORDERS.md, правило 13).
2. **Сверка автоматическая.** Резерв, снятие резерва и пометки ставит только сверка, руками — никогда. Повторный
   запуск ничего не меняет.
3. **Резерв — из самой старой поставки** (по дате), как требует склад (WAREHOUSE.md, правило 6).
4. **Кто раньше заказал, тому и джинса.** Сверка обходит заказы от старых к новым.
5. **Заказ с проблемой в очередь не идёт** и не печатается.
6. **Заказ в партии на пульте в очереди не показывается** — второй раз его в партию не отправить.
7. **Партия уходит в порядке очереди,** а не в порядке кликов по галочкам.
8. **«Собран» ставит только «Партия расклеена»** — и только заказам без ошибки, которые всё ещё «Заказан», без
   проблемы и с резервом (ORDERS.md, правила 9 и 14).
9. **Заказ с ошибкой расклейки остаётся «Заказан»** и снова попадает в очередь.
10. **Вернуть в очередь можно только нерасклеенную партию.**
11. **Партии не удаляются.** Возврат в очередь и расклейка ставят отметку, партия остаётся в истории пульта.
12. **Расклеенная партия больше не меняется.**
13. **Экраны статусы Авито не трогают:** комплектация только собирает партии, пульт ставит только «Собран».
14. **Порядок очереди один и автоматический:** Категория → Товар → Размер → Служба. Пресетов и ручной перестановки
    уровней нет; меняется только порядок служб.
15. **Срочность — только внутри группы.** Срок отгрузки (`shipBy`) поднимает заказ наверх своей группы
    (товар · размер · служба), но из группы не вынимает.
16. **Быстрая печать — сначала состав, потом партия.** Партия с пульта создаётся только после показа состава и
    подтверждения, в порядке очереди. Обходить очередь она не может: берёт те же заказы «К печати».
17. **Выбор «Что печатать» один на оба экрана** — общий компонент `QueueFilter` и общие функции в
    `shared/fulfillment/queue.ts`. Своих фильтров у экранов нет.
18. **«Напечатана» — только когда принтер принял бирки.** `printedAt` ставится после успешной отправки, без принтера
    отметить партию напечатанной нельзя. Ошибка — партия остаётся «Ждёт печати».
19. **Бирки партии уходят одним заданием в порядке партии.** Печатаем только заказы, которые всё ещё «Заказан» или
    «Собран»; отменённые и не найденные пропускаются.
20. **Перепечатка — только до расклейки** и всегда пишется в историю партии (`reprints`); `printedAt` не меняется.

## 5. Сверка со складом

`syncReserves(заказы, модели)` в `shared/fulfillment/reserve.ts` — чистая функция: возвращает новые заказы и модели
или `null`, если менять нечего.

Заказы обходятся от старых к новым (`createdAt`):

| Заказ | Что делает сверка | На полке |
|---|---|---|
| «Заказан», модели товара нет (объявление без товара) | пометка «Товар не выбран», резерв (если был) снят | 0 / +1 |
| «Заказан» без размера | пометка «Без размера» | 0 |
| «Заказан» / «Собран» с размером, резерв уже есть | снимает пометку | 0 |
| «Заказан» / «Собран» с размером, резерва нет, джинса есть | резерв: джинса из самой старой поставки, `Unit { order, orderDate ДД.ММ, status: reserve, batchId }`, пометка снимается | −1 |
| «Заказан» с размером, джинсы нет | пометка «Нет на складе» | 0 |
| «Отменён» с резервом | резерв снят, джинса на полку **своей** поставки, пометка снимается | +1 |
| «Заказан» / «Собран», резерв в другом размере или другой модели (размер поменяли, объявление перепривязали) | старый резерв снят на полку своей поставки, дальше как выше | +1 |
| Остальные статусы | снимает пометку проблемы (заказ ушёл дальше — например, Авито прислал «Едет к покупателю») | 0 |

- Модель ищется по id (`Order.productId` = `Model.id`), размер — по номеру. У заказа из Авито `productId` (и название
  в `product`) перед сверкой ставит `syncProducts` по привязке объявления (ORDERS.md, раздел 7). Старый резерв ищется
  во всех моделях. Переименование модели или категории резерв и очередь не ломает: название в заказе подтягивается.
- Записи `stock` с нулём удаляются (как требует склад).
- **Когда запускается** (`startReserveSync` в `shared/fulfillment/store.ts`, вызывается в `main.tsx`): при старте
  приложения и после каждого изменения заказов, склада или привязок объявлений — на любом экране. Добавил поставку на складе —
  заказы с «Нет на складе» сразу встают в резерв.
- Пока не делает: статус джинсы после отправки (`sent`, `delivered`) и возвраты из заказа не выводятся.

## 6. Как считаются цифры

`shared/fulfillment/queue.ts`, `shared/fulfillment/batches.ts`.

### Комплектация

- **Очередь** `buildQueue` — заказы с этапом «К печати». Для каждого запоминаются позиции для сортировки.
- **Всего** — заказы с этапом Проблема, К печати, В партии или Напечатан. Под цифрой: «к печати N · в партиях M ·
  проблем K» (в партиях = В партии + Напечатан).
- **На печать** — вся очередь, без фильтров.
- **Товаров** — сколько разных моделей в очереди. Под цифрой — «модель количество» через « · » в порядке склада.
- **ПВЗ** — сколько разных служб в очереди. Под цифрой — все службы с количеством, нули тоже, в порядке служб.
- **Проблемы** — заказы с этапом «Проблема».
- **Отпечатано сегодня** — партии (кроме возвращённых) с `printedAt` сегодня (местный день) и сумма штук в них.
- **Счётчики на чипах выбора** — по всей очереди без выбора. Размеры считаются в пределах своего товара.
- **Счётчик «Очередь печати N»** — после выбора.

### Порядок очереди

`sortQueue` — всегда одинаково. Логика расклейки: подошёл к полке товара, расклеил один размер сразу по стопкам
служб, потом следующий размер.

| Ключ | Порядок |
|---|---|
| 1. Категория | как категории в настройках склада; модели без категории — в конце |
| 2. Товар | как модели на складе (порядок массива моделей) |
| 3. Размер | как размеры у своей модели (настраивается на складе) |
| 4. Служба доставки | порядок служб (раздел 3), по умолчанию Яндекс → Авито → СДЭК → Почта → 5Post → DPD |
| 5. Срок отгрузки | внутри группы: самые ранние и просроченные сверху, без срока — в конце |
| 6. Время заказа | при равных сроках — кто раньше заказал (`createdAt`) |

Срок стоит после всех ключей группы, поэтому заказ из своей группы не вылезает (правило 15).
**Просрочен** (`isOverdue`) — `shipBy` раньше сегодняшнего местного дня.

### Группы

`groupQueue`: подряд идущие заказы с одним товаром, размером и службой — одна группа, одна стопка.
Заголовок — «Товар · Размер · Служба»: «Джинсы Клёш · 30S · СДЭК». Разделительной бирки между группами нет.

### Выбор «Что печатать»

`filterQueue(очередь, выбор)` / `matchesSelection`: заказ подходит, если его служба отмечена **и** его товар отмечен
(а если у товара выбраны размеры — и размер среди них).
- **«Все»** — выбраны все товары и все службы, все чипы отмечены. По умолчанию.
- **По товару:** чипы товаров, которые есть в очереди, в порядке склада. Снял хоть один из «всех» — включается выбор
  по товару, отмеченными остаются остальные (`toggleProduct`).
- **Размеры товара:** у отмеченных товаров, где в очереди больше одного размера, — свои чипы размеров в порядке
  размеров модели. Снял размер — у товара в партию идут только отмеченные размеры (`toggleSize`). Снял последний
  размер — снят и товар.
- **По службе:** чипы всех шести служб, с нулями, в порядке служб; снял — в партию идут только отмеченные
  (`toggleService`).
- Отметил обратно всё — выбор снова «Все» (чип «Все» горит). Клик по «Все» сбрасывает выбор.
- Сняли все товары или все службы — не подходит ничего.
- Товар, который появился в очереди после выбора по товару, в выбор не попадает, пока его не отметят (или «Все»).

### Подпись партии

`describeSelection`: «Категория → Товар → Размер → Служба», и если выбор не «Все» — « · только » и отмеченные
товары (с размерами в скобках, если выбраны) и службы через запятую: «… · только Джинсы Клёш (30S, 31M), СДЭК».

### Пульт

- **Ждут печати** / **Ждут расклейки** — партии в состоянии Ждёт печати / Напечатана и сумма штук.
- **Быстрая печать:** «в очереди N» — вся очередь (как «На печать» в комплектации); «Собрать партию (N)» — после
  выбора; состав — группы очереди (`groupQueue`) после выбора с количеством, итог «K групп · N шт.».
- **Расклеено сегодня** — партии с `stuckAt` сегодня; штук собрано = штук в них минус ошибки.
- **Ошибок сегодня** — сумма ошибок в партиях, расклеенных сегодня.
- В карточке: состав — «модель размер ×N» в порядке первого появления в партии; службы — «служба ×N»;
  «собрано N» при подтверждении — заказы партии, которые сейчас «Заказан» и без отмеченной ошибки.

## 9. Хранение

Общее состояние — `shared/lib/store.ts` (`createFileStore` — файлы сервера данных, `createStore` — только браузер):
одно на все экраны, экраны подписаны и обновляются сами.

| Что | Файл сервера данных / ключ | Где |
|---|---|---|
| Партии печати | **`printBatches.json`** `{ batches }` | `shared/fulfillment/store.ts` |
| Заказы (статусы, пометки) | `orders.json` | `shared/orders/index.ts`, см. ORDERS.md |
| Склад (резервы) | `catalog.json` + `stock.json` | `shared/stock/store.ts`, см. WAREHOUSE.md |
| Порядок служб | **`shop.json`**, поле `serviceOrder` (остальные поля магазина — бота, не трогаем) | `shared/fulfillment/serviceOrder.ts` |
| Выбор «Что печатать» в комплектации | `hubbro.picking.queue.v4` (браузер) | `features/picking/PickingPage.tsx` — удобство одного браузера |

- Пусто или повреждено → пусто: заказов и партий нет, выбор «Все», порядок служб по умолчанию. Тестовых данных
  нет (чистый старт); старые версии ключей не читаются и при запуске удаляются из браузера.
- Очистить всё — Настройки → «Данные» → «Очистить все данные» (SETTINGS.md).
- Если меняется формат — только вместе с FORMAT.md (версия файла, миграция).
- Партии и порядок служб синхронизируются с сервером данных, выбор «Что печатать» — нет, он свой у браузера.
  Выбор быстрой печати на пульте не хранится вовсе. Синхронизация — [ARCHITECTURE.md](ARCHITECTURE.md), «Сервер и данные».
- Когда появится бэкенд, меняются только `store.ts`; логика (`reserve.ts`, `batches.ts`, `queue.ts`) остаётся.

**Действия** (`shared/fulfillment/store.ts`):

| Действие | Кто вызывает | Что делает |
|---|---|---|
| `createBatch(orderIds, note)` | комплектация, быстрая печать на пульте | новая партия с номером max+1, возвращает номер |
| `markPrinted(id)` | пульт, «Напечатать», после того как принтер принял бирки | `printedAt` |
| `markReprinted(id, orderId?)` | пульт, «Перепечатать партию» / «Перепечатать» | запись в `reprints` |
| `cancelBatch(id)` | пульт, «Вернуть в очередь» | `cancelledAt` |
| `markStuck(id, issues)` | пульт, «Партия расклеена» | заказам без ошибки (Заказан, без проблемы, с резервом) — запись «Собран» в историю; партии — `stuckAt`, `issues`, `printedAt` если не было. Повторно не срабатывает |
| `startReserveSync()` | `main.tsx`, один раз | сверка сразу и после каждого изменения заказов, склада или привязок объявлений |
