# Настройки — документация

Раздел кабинета, где хранятся данные подключений к внешним сервисам и настройки принтера. Позже здесь же появятся
вход и доступы.

**Как пользоваться документом:** перед работой с настройками (`web/src/features/settings/`) читай его; после
изменения (поля, логика, тексты) обнови нужные разделы и журнал внизу в том же коммите.

---

## 1. Меню

Порядок разделов слева: **Пульт → Комплектация → Склад → Заказы → Объявления → Настройки**. Порядок задаёт список в
`web/src/app/routes.tsx`. Открывается по умолчанию пока Склад (`defaultPath`).

## 2. Экран

Шапка «Настройки», под ней пояснение «Ключи Авито и Telegram и настройки принтера хранятся только в этом браузере
и на сервер не уходят» и шесть **раскрывающихся разделов**: Авито, Telegram-бот, Расширение Авито, Принтер,
Авторизация, Данные. В шапке раздела — название, одна строка «зачем», статус и стрелка;
клик раскрывает или сворачивает. Открытыми могут быть несколько сразу; при заходе на страницу все свёрнуты.

## 3. Подключения Авито и Telegram

Поля с кнопками «Сохранить» / «Отменить» / «Стереть».

### Авито

| Поле | Ключ | Обязательное | Что это |
|---|---|---|---|
| Client ID | `clientId` | да | Ключ API из профиля Авито (Для профессионалов → API) |
| Client secret | `clientSecret` | да, секрет | Секрет к Client ID |
| Номер профиля | `userId` | да | Номер аккаунта продавца — нужен для запросов сделок |

Зачем: по ним забираем объявления ([LISTINGS.md](LISTINGS.md)), а потом оплаченные сделки и их статусы
(см. [ORDERS.md](ORDERS.md), [ROADMAP.md](ROADMAP.md)).

### Telegram-бот

| Поле | Ключ | Обязательное | Что это |
|---|---|---|---|
| Токен нашего бота | `botToken` | да, секрет | Выдаёт @BotFather |
| Бот Гришки | `sizeBot` | да | @username или ID бота, чьи сообщения принимаем как размеры |
| Чат обмена | `chatId` | нет | ID группы, если обмен ботов идёт через группу |

Зачем: размеры от бота Гришки и команда «спроси размер» (ROADMAP, «Связь с ботом Гришки»). Схема «бот читает
бота» ещё не проверена — поля могут поменяться.

## 3а. Расширение Авито

Расширение Chrome забирает заказы из кабинета Авито — подробно [EXTENSION.md](EXTENSION.md). Раздел
(`features/settings/AvitoExtension/`):
- статус «На связи» (зелёный), когда расширение ответило кабинету, иначе «Не установлено» (серый);
- на связи — строка «Расширение 0.2.0 на связи…», нет — три шага установки; во втором — «Уже стоит — обновите
  папку и нажмите «Обновить»: сайт видит версия 0.2.0 и новее» (0.1.0 работало только с localhost);
- **«Вставить заказы»** — поле для текста, скопированного кнопкой «Скопировать» на странице Авито, и кнопка
  «Принять заказы»: под ней итог («BRO x BRO SHOP: 5 новых, 12 обновлено, 3 без изменений» и предупреждения)
  или ошибка «Это не заказы из расширения…».

## 4. Принтер

Xprinter XP-365B: термопечать без ленты, 203 dpi (8 точек на мм), ширина бирки 20–80 мм, до 5 дюймов в секунду,
USB, язык команд TSPL. Наша бирка — 40×58 мм (ROADMAP). Код — `shared/printer/`: им пользуются и настройки
(пробная печать), и пульт — печать партий с **сохранёнными** настройками (PICKING.md, раздел 8a).

### Как печатаем — WebUSB (решено 16.11.2026)

Chrome сам говорит с принтером по USB: **без драйвера, без программы на компьютере, без окна печати.**

1. Один раз в «Настройки → Принтер» жмём **«Подключить принтер»** — Chrome показывает список USB-устройств,
   выбираем Xprinter. Без клика человека браузер к USB не пускает. Выбор Chrome запоминает, у нас в
   localStorage — какой это принтер (`hubbro.printer.device.v2`: коды производителя и модели, серийный номер, имя).
2. Бирку рисуем сами на холсте в точках принтера (80×50 мм = 640×400) и переводим в чёрно-белое (раздел
   «Бирка»).
3. Картинку отправляем командой TSPL `BITMAP`. Задание: `SIZE`, `GAP`, `DENSITY`, `SPEED`, `DIRECTION`,
   `REFERENCE` один раз, дальше на каждую бирку `CLS → BITMAP → PRINT 1,1`. В `BITMAP` бит 1 — белая точка, 0 —
   чёрная.
4. Байты уходят в bulk OUT канал устройства (лучше у интерфейса класса «принтер», 7) кусками по 16 КБ. Задания идут
   по очереди, чтобы партии не перемешались.

**Ограничения:**
- Только Chrome или Edge (Safari не умеет WebUSB), сайт по `https` или `localhost`.
- Принтер **не добавлять в системные принтеры Mac** и не ставить драйвер — иначе macOS может перехватить его и
  Chrome получит «нет доступа».
- Принтер держит одна вкладка: в другой вкладке будет «нет доступа».
- WebUSB подтверждает только, что принтер **принял данные.** Кончилась лента или замяло — видно глазами, для этого
  на пульте есть «Бирка не напечаталась».
- **Windows:** если на принтере стоит драйвер (Xprinter или стандартный драйвер USB-принтера Windows), Chrome
  получает «нет доступа» (`SecurityError` / «Unable to claim interface»). Один раз меняем драйвер на WinUSB:
  Zadig (zadig.akeo.ie) → Options → List All Devices → Xprinter → WinUSB → Replace Driver, переткнуть принтер и
  подключить заново. После этого из обычных программ Windows на нём не печатается — только из кабинета.
- Текст ошибки «нет доступа» — под систему (`shared/printer/usb.ts`, `NO_ACCESS`): на Windows — про драйвер и
  шаги Zadig, на Mac — про другую вкладку и системные принтеры macOS.
- Привязки принтера к аккаунту или компьютеру нет: выбор живёт только в этом браузере. Принтер по USB печатает
  с того компа, в который воткнут; переткнули в другой — там один раз «Подключить принтер».

**«Отключить принтер»** — кнопка в строке подключения, видна, когда принтер выбран («Подключён» или «Не найден»),
рядом с «Выбрать другой». После подтверждения браузер забывает выбранный принтер и **все** USB-устройства, к которым
Chrome дал доступ сайту (`forgetPrinter`), статус — «Не подключён». Затрагивает только этот браузер.

**Запасной вариант,** если WebUSB не заведётся: драйвер Xprinter + окно печати браузера, бирка — страница 80×50.
**Print Agent** (программа на компьютере) — только если понадобится печать по сети (порт 9100), с сервера без
открытого пульта или из Safari. Пока не делаем.

### Статус

| Состояние | Бейдж раздела | Когда |
|---|---|---|
| `unsupported` | Нужен Chrome (красный) | В браузере нет WebUSB |
| `notPaired` | Не подключён (серый) | Принтер ещё не выбирали |
| `notFound` | Не найден (жёлтый) | Выбран, но сейчас не воткнут или выключен. Воткнули — подхватится сам |
| `ready` | Подключён (зелёный) | Выбран и на связи |

Тот же бейдж («Принтер: …») стоит на пульте у заголовка «На пульте» (`PRINTER_STATUS` в `shared/printer/status.ts`).
Печатать партии можно только в «Подключён»; иначе на пульте ссылка «настройки →» ведёт на `/settings#printer` —
раздел «Принтер» открывается раскрытым.

### Бирка

Вертикальная, 40 мм в ширину, 58 в высоту (320×464 точки); раскладка масштабируется под другие размеры. Две
раскладки, печатается выбранная в настройках (поле `layout`); данные одни и те же.

```
 «С названием» (full)        «Без названия» (compact)
┌──────────────────┐        ┌──────────────────┐
│ [ЛОГО]  Джинсы   │        │      [ЛОГО]      │
│ [    ]  Клёш     │        │                  │
│ N033529-КЛ       │        │       33L        │
│       33L        │        │ N033529-КЛ       │
│ ▌█▌▌█▌▌█▌▌█▌▌█▌  │        │ ▌█▌▌█▌▌█▌▌█▌▌█▌  │
│ 805 122 273 33459│        │ 805 122 273 33459│
│      Авито       │        │      Авито       │
└──────────────────┘        └──────────────────┘
```

- **Лого** 14×14 мм (`public/logo.png`). Свой логотип загружать — позже.
- **Название товара** (модель склада) — только в «С названием»: справа от лого, автоподбор шрифта, до 3 строк.
  Максим попросил вариант без него.
- **Номер** — `N` + последние 6 цифр номера заказа Авито (`70000000566033529` → `N033529`), через дефис **код
  модели** со склада (`-КЛ`, WAREHOUSE.md). Нет кода — без приписки.
- **Размер** — крупно по центру.
- **Штрихкод Code128 с номером отправления** — тем же, что Авито показывает в карточке заказа и что пикают в ПВЗ.
  Цифры кодируются парами (набор C), буквы — набором B (`shared/printer/code128.ts`, без библиотек). Модуль —
  целое число точек, самое большое до 3, которое влезает между белыми полями по 2,5 мм: 10 цифр Авито — 3 точки,
  13–14 цифр Почты, `P04…` Яндекса и 5Post, `RU…` DPD — 2 точки. Проверено распознавателем штрихкодов Chrome на
  номерах всех служб, кроме DPD: у него пока сверена только ширина (как у Яндекса).
- **Нет номера отправления** (ещё не оформили отправку) — вместо штрихкода рамка «Нет номера отправления»,
  чтобы такую бирку не наклеили как готовую.
- Под штрихкодом номер отправления группами, как у Авито (`805 122 273 33459`), ниже служба — куда нести.
- Текст шрифтом Onest, с кириллицей: встроенные шрифты принтера её не знают, поэтому бирка уходит картинкой.
- Чёрно-белое по порогу яркости 140: принтер не умеет серый.
- **Превью = печать:** в настройках обе раскладки показаны тем же холстом, что уходит принтеру (пример заказа);
  клик по превью выбирает раскладку.
- **Ориентация печати** (поле `orientation`) — как бирка ложится на ленту; сама бирка всегда вертикальная.
  «Вертикальная» (по умолчанию) — лента идёт широкой стороной (58 мм) поперёк: картинку поворачиваем на 90° по
  часовой по точкам, принтеру уходит `SIZE 58 mm,40 mm`. «Горизонтальная» — картинка как нарисована, `SIZE 40 mm,58 mm`.
  Первая пробная печать без поворота вышла боком — поэтому по умолчанию поворачиваем. Вышло вверх ногами —
  «Перевернуть бирку».

### Поля

| Поле | Ключ | По умолчанию | Границы |
|---|---|---|---|
| Раскладка | `layout` | «С названием» (`full`) | `full` / `compact` |
| Ширина бирки | `labelWidth` | 40 мм | 20–80 |
| Высота бирки | `labelHeight` | 58 мм | 10–200; при вертикальной печати до 80 — она идёт поперёк ленты |
| Зазор между бирками | `gap` | 2 мм | 0–10 |
| Плотность | `density` | 8 | 0–15 |
| Скорость | `speed` | 4 дюйм/с | 2–5 |
| Ориентация печати | `orientation` | Вертикальная (`vertical`) | `vertical` — повернуть на 90°, `horizontal` — как есть |
| Перевернуть бирку | `flip` | нет | `DIRECTION 0` вместо `1` |

Хранятся в localStorage, ключ `hubbro.printer.v2` (в `v1` была бирка 80×50 — старые настройки не переносятся). «Сохранить» неактивно, пока число вне границ (поле краснеет).
«По умолчанию» (с подтверждением) возвращает значения из таблицы.

### Пробная печать

Одна бирка-пример с **текущими значениями формы, даже несохранёнными** — чтобы подобрать плотность и зазор, не
сохраняя каждый раз. Активна, когда принтер «Подключён» и числа в границах. Под формой — «Отправлено в 12:30» или
понятная ошибка (нет доступа, связь прервалась, принтер не найден).

### Проверить на живом принтере

1. Видит ли Chrome принтер и отдаёт ли его macOS без драйвера.
2. Понимает ли наш экземпляр TSPL сразу (у некоторых Xprinter режим «чеки / бирки» переключается кнопкой).
3. Ориентация: при «Вертикальной» бирка должна выйти стоя; если нет — «Горизонтальная» и/или «Перевернуть».
4. Направление (`flip`), плотность, зазор, читает ли штрихкод сканер ПВЗ и телефон (модуль 0,25 мм), как выглядит
   логотип.
5. Коды производителя и модели — поставить фильтр в окошко выбора, чтобы показывать только принтер.

## 5а. Данные — «Очистить все данные»

Кабинет как при первом запуске: начать с чистого листа и пройти все шаги заново. Раздел последний, статус
«Осторожно».

- Что удаляется: склад (модели, категории, поставки, остатки, черновики, отображение), заказы, партии печати,
  объявления и привязки, порядок служб (по умолчанию) — **у всех, на сервере данных тоже**; ключи Авито и Telegram,
  настройки принтера, выбранный принтер (Chrome забывает доступ к USB — `forgetPrinter`), выбор «Что печатать» —
  в этом браузере.
- Каталог общий с ботом ([avito/data/schema/FORMAT.md](../../data/schema/FORMAT.md)): модели, у которых есть данные
  бота (описание, сетка, фото, слова), **остаются** в каталоге — без поставок, остатков и полей кабинета (код, архив,
  скрытые размеры, пороги, пачки), с их категориями. Остальные модели и пустые категории удаляются. Общая история
  (`log.json`) не стирается — в неё пишется «Кабинет очищен…». Название магазина, наличие и время отправки
  (`shop.json`) не трогаются.
- Что остаётся: ключ доступа к серверу `hubbro.access.v1` — это не данные, без него кабинет просто спросит снова.
  На других компах ключи Авито/Telegram и принтер свои, их кнопка не трогает (они только в браузере).
- Подтверждение тут же: «Очистить все данные» → «Удалить всё безвозвратно? Это не отменить.» → «Да, очистить» /
  «Отмена».
- Как: файлы кабинета сбрасываются (как выше) и сразу уходят на сервер данных (`flushServerSync`), другие компы подтянут
  пустое при опросе. Сервер не принял — ошибка текстом, браузер дальше не чистим. Потом удаляются браузерные ключи
  `hubbro.*` и страница перезагружается.
- Нет связи с сервером (или ещё подключаемся) — кнопка неактивна: «Нет связи с сервером — очистить нельзя, иначе
  старые данные вернутся». Работаем без сервера — чистится только браузер.
- Код: `features/settings/ClearData/`, `features/settings/clearData.ts`.

## 6. Правила

1. Секреты на экране скрыты точками, пока не нажали «Показать».
2. «Стереть» — только с подтверждением.
3. Пробелы по краям при сохранении обрезаются, пустые поля не сохраняются.
4. Статус карточки: «Не подключено» — ничего не внесено; «Заполнено не всё» — не хватает обязательного поля;
   «Данные внесены» — все обязательные поля есть. **Рабочие ли ключи, не проверяем** — без сервера нельзя.

## 7. Хранение

Значения лежат только в localStorage этого браузера — в базу на сервере (`/api/state`) не попадают, ключ
`hubbro.connections.v2` (`avito`, `telegram`): на сайте https://hub-bro.vercel.app их вносят в каждом браузере
отдельно. Запросы к Авито с сайта идут через переадресацию Vercel `/avito/*` → `api.avito.ru` (`web/vercel.json`):
ключи проходят через неё к Авито, но нигде не сохраняются. Настройки принтера — отдельно, `hubbro.printer.v3`; выбранный
принтер — `hubbro.printer.device.v2`. Версии подняты при чистом старте: на первом запуске ключей и принтера нет,
старые ключи удаляются из браузера. **До живого запуска** данные переезжают на сервер: секреты не должны жить в браузере, а запросы к
Авито и Telegram идут с сервера. Тогда же появится кнопка «Проверить подключение».
