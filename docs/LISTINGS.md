# Объявления — документация

Раздел «Объявления»: все объявления аккаунта Авито и их привязка к **моделям склада**. Зачем: на Авито у одного
товара бывает 5–10 объявлений с разными названиями («Джинсы широкие трубы прямые zara rick owens type»,
«Джинсы трубы широкие прямые Zara Y2K Rick Owens»…), а склад знает одну модель «Джинсы Трубы». По привязке заказ
узнаёт, какую джинсу брать с полки.

**Как пользоваться документом:** перед работой с объявлениями (`web/src/features/listings/`,
`web/src/shared/listings/`, `web/src/shared/avito/api.ts`) читай его; после изменения обнови нужные разделы и журнал
внизу в том же коммите. Задело склад или заказы — обнови и [WAREHOUSE.md](WAREHOUSE.md) / [ORDERS.md](ORDERS.md).

---

## 1. Словарь

| Термин | Что это |
|---|---|
| **Объявление** | Объявление на Авито. Ключ — **ID Авито**: он не меняется, даже если поменять название или цену. |
| **Товар** | Так на экране называется модель склада («Джинсы Клёш»), к которой привязано объявление. |
| **Без товара** | Объявление, которое ещё ни к чему не привязали (или его модель удалили). Его надо разобрать. |

## 2. Что хранится

Типы — `shared/listings/types.ts`.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | ID объявления на Авито |
| `title` | string | Название на Авито, как есть |
| `price` | number | Цена на Авито, ₽ |
| `status` | `ListingStatus` | Статус на Авито (раздел 4) |
| `url` | string | Ссылка на объявление |
| `category`, `address` | string | Категория и адрес на Авито |
| `productId` | string \| null | **Привязка:** id товара каталога (= `Model.id` склада). `null` — без товара. Раньше поле называлось `modelId` |
| `linkedAt?` | ISO | Когда выбрали товар |
| `stats?` | `{ views, contacts, favorites }` | Уникальные просмотры, контакты, добавления в избранное за 30 дней |
| `firstSeenAt` | ISO | Когда впервые пришло при обновлении |
| `syncedAt` | ISO | Когда последний раз пришло с Авито |
| `goneAt?` | ISO | Авито перестал его отдавать (удалено насовсем) |

**Привязка хранится только у объявления** (`productId`). У модели склада ничего не хранится — «у модели 9 объявлений»
считается на лету. Так данные не разъедутся. Ссылаемся на `id` модели, а не на название: модель можно
переименовать, привязки останутся.

**Заказ берёт товар отсюда.** У заказа из Авито есть ID объявления (`itemId`). Перед сверкой со складом
`syncProducts` ставит заказу в «Заказан» / «Собран» товар (`productId` и название в `product`) = модель, к которой привязано объявление
([ORDERS.md](ORDERS.md), раздел 7). Не привязано — заказ с проблемой «Товар не выбран». Привязал, перепривязал или
отвязал — заказы и резервы перестраиваются сами.

### Хранение

`shared/listings/index.ts` (`listingsStore`, `useListings()`) — файл **`listings.json`** сервера данных avito
`{ format: "listings", version: 1, listings, syncedAt }` (формат — [avito/data/schema/FORMAT.md](../../data/schema/FORMAT.md)),
в браузере копия `hubbro.data.listings`. Объявления читает и бот (по `productId` узнаёт товар). Тестовых данных нет:
пусто, пока не обновили с Авито. Старый ключ `hubbro.listings.v2` не читается и удаляется при запуске; запись со
старым `modelId` читается как `productId`. Очистить — Настройки → «Данные». Синхронизация — ARCHITECTURE.md,
«Сервер и данные».

## 3. Откуда берём

API Авито с ключами из «Настройки → Авито» (`shared/connections`). Клиент — `shared/avito/api.ts`: токен
(client_credentials, живёт час, держим в памяти), понятные ошибки, номер профиля из настроек или
`/core/v1/accounts/self`.

| Запрос | Что даёт | Когда |
|---|---|---|
| `GET /core/v1/items?status=active,removed,old,blocked,rejected` | ID, название, цена, статус, ссылка, категория, адрес. По 100 на страницу | «Обновить с Авито» |
| `POST /stats/v1/accounts/{профиль}/items` | Просмотры, контакты, избранное за 30 дней, до 200 объявлений за запрос | вместе с обновлением; не ответила — объявления всё равно сохраняются |
| `GET /core/v1/accounts/{профиль}/items/{id}/` | Когда размещено и до какого числа показывается | когда раскрыли карточку |

**Фото API не отдаёт** — карточки без фото. Можно потом брать главную картинку со страницы объявления.

**Прокси.** Браузер к `api.avito.ru` напрямую не пускает (CORS), поэтому запросы идут на `/avito/...`, а
дев-сервер Vite пересылает их на `https://api.avito.ru/...` (`web/vite.config.ts`). Значит, обновление работает
при `npm run dev` через прокси дев-сервера, на Vercel — через `rewrites` в `web/vercel.json`. С бэкендом запросы и ключи уйдут на сервер.

### Обновление (`mergeListings`)

- Пришло новое — добавляем без товара, `firstSeenAt` = сейчас.
- Уже было — обновляем название, цену, статус, ссылку, статистику. **Привязку не трогаем.**
- Было, а Авито больше не отдаёт — **не удаляем**, ставим `goneAt`: по нему могут быть заказы и возвраты.
  Вернулось — `goneAt` снимается.
- Сами обновляемся при заходе на страницу, если ключи есть и с прошлого раза прошло больше 10 минут.

## 4. Статусы

| Статус Авито | Подпись | Цвет |
|---|---|---|
| `active` | Активно | зелёный |
| `old` | Срок вышел | серый |
| `removed` | Снято | серый |
| `blocked` | Заблокировано | красный |
| `rejected` | Отклонено | красный |
| есть `goneAt` | Нет на Авито | серый |

Нет товара — рядом жёлтый бейдж «Без товара».

## 5. Правила

1. **Ключ объявления — ID Авито.** Название и цена меняются, ID нет.
2. **Одно объявление — одна модель.** Одна модель — сколько угодно объявлений.
3. **Привязка хранится только у объявления.** Счётчики у моделей считаются.
4. **Обновление с Авито привязку не трогает.**
5. **Объявления не удаляются.** Пропало с Авито — пометка `goneAt`.
6. **Модель удалили — её объявления становятся «без товара»** (`unlinkModel`). Модель в архиве — привязка остаётся,
   но в выборе товара архивных моделей нет (кроме уже выбранной, с пометкой «в архиве»).
7. **Отвязка в настройках склада пишется в историю склада** (правило 16 склада). Выбор товара на странице
   объявлений в историю склада не пишется — это не настройка склада.

## 6. Экран «Объявления»

Пункт меню между «Заказами» и «Настройками».

- **Шапка:** «Объявления», под ней «Обновлено 16 ноября в 15:30 · 35 объявлений». Справа поиск (по названию или
  ID, пробелы не важны) и «Обновить с Авито». Без ключей кнопка неактивна, ниже — ссылка в Настройки.
  Ошибка обновления — красной плашкой: неверные ключи, нет связи, Авито просит подождать, нет дев-сервера.
- **Чипы:** `Без товара N` (красный, пока есть что разбирать) · `Активные N` · `Все N`. Пока есть объявления без
  товара, открываются они; иначе — все. Поиск ищет по всем. `/listings?q=…` открывает страницу сразу с поиском —
  так ведёт ссылка «выбрать товар →» из заказа.
- **Ждут заказы.** Объявление без товара, по которому есть заказы с «Товар не выбран», — красный бейдж
  «⚠ Ждут заказы: N», такие идут первыми.
- **Бенто-сетка карточек** (от 280 px в ширину). Порядок: активные первыми, внутри свежие сверху. От привязки порядок
  не зависит — выбрал товар, карточка не прыгает (в «Без товара» она уходит из списка).
- **Карточка:** статус (и «Без товара»), цена, название (2 строки), «358 просм. · 5 конт. · 8 в избр. за 30 дней»,
  внизу **«Товар»** — поле с поиском (`ProductPicker/`, не системный список). Без товара поле жёлтое
  («Выберите товар»).
- **Выбор товара:** клик или фокус открывает чёрный список в стиле сайта: модели склада по категориям (архивные
  не показываются, кроме уже выбранной — «(в архиве)»), у выбранной галочка, внизу красное «Отвязать товар».
  Ввод фильтрует по названию модели и категории: все слова должны найтись, «ё» = «е» («клеш» → «Джинсы Клёш»).
  Ничего не нашлось — «Такой модели на складе нет». Стрелки — по списку, Enter — выбрать, Esc или клик мимо —
  закрыть без изменений.
- **Клик по карточке** раскрывает подробности: ID на Авито, когда размещено и до какого числа показывается,
  категория, адрес, «У нас с … , товар выбран …», «Пропало с Авито», ссылка «Открыть на Авито ↗».

### На складе

- Плитка модели: под категорией «9 объявлений» (если есть хоть одно).
- Настройки склада → карточка модели: в шапке «· 9 объявлений», внутри раздел **«Объявления на Авито (9)»** —
  название (ссылка на Авито), цена, статус, ID и крестик «Отвязать». Пусто — подсказка со ссылкой на «Объявления».
