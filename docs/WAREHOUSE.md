# Склад — полная документация

Единственный источник правды по складу HUB BRO: что хранится, какие правила нельзя нарушать, как считаются
цифры, как работают экраны.

**Как пользоваться документом:**
- перед любой работой со складом читай его;
- после любого изменения склада (логика, данные, экраны, тексты) обнови нужные разделы в том же коммите.

Код: экран — `web/src/features/stock/`; типы, расчёты и само состояние — `web/src/shared/stock/`
(склад меняет и комплектация: резервы под заказы). Тестовых данных нет: склад начинается пустым, данные — на
сервере данных avito в общем формате [avito/data/schema/FORMAT.md](../../data/schema/FORMAT.md) (`catalog.json` +
`stock.json` + `hub.json` + `log.json`) и копией в браузере (см. «Хранение»).

## 1. Словарь

| Термин | Что это |
|---|---|
| **Категория** | Группа моделей: Джинсы, Куртки. Обязательна у каждой модели. Хранит шаблон размеров и пороги по умолчанию. |
| **Модель** | Конкретный товар: «Джинсы Клёш», «Джинсы Трубы», «Куртка Дутая». Цветов нет: другой цвет — другая модель («Клёш чёрные»). В общем формате это **товар каталога** (`Product`) — тот же, о котором рассказывает бот; модель = товар + его поставки и остатки. |
| **Размер** | Номер строкой: «30». Буква — в шкале магазина (`catalog.sizeScale`), на экране «30 (M)», в плотных сетках — просто номер. Новый номер (в поставке или настройках) сам попадает в шкалу без буквы. |
| **Поставка** (= партия) | Приход **одной модели** за один день от одного поставщика. Вносится **сумма за всю поставку**, цена за штуку считается сама. |
| **На полке** | Безликие джинсы: все 31-е одной кучей, хранятся количеством по поставкам. |
| **Джинса с заказом** (единица) | Джинса, к которой привязан заказ. С этого момента она уникальная и проходит по статусам. |
| **Пачка** | Готовый набор размеров одной модели, «Стандарт: 28S … 33L». **Всегда по одной штуке каждого размера.** Хранится у модели, нужна только чтобы быстро вносить поставку: на складе пачек нет, только размеры. |
| **Черновик** | Незаконченное окно «+ Поставка», сохранённое, чтобы дописать потом. |
| **Пороги** | Числа «мало до» и «норм до», по которым красится остаток. Есть у категории, у модели могут быть свои. |
| **Архив** | Модель «на полке у бухгалтера»: не видна на складе и в поставке, в истории остаётся. Вместо удаления. |
| **Скрытый размер** | Размер, который не показывается на складе и в поставке. Скрыть можно только пустой. |
| **Объявление** | Объявление Авито, привязанное к модели. У модели их может быть сколько угодно. Привязка хранится у объявления — [LISTINGS.md](LISTINGS.md). |

## 2. Что хранится

Типы — `shared/stock/types.ts`.

### Модель (`Model`)

Модель — склейка товара каталога (`Product`, `catalog.json`) и его поставок и остатков (`stock.json`), см. «Хранение».
Поля товара, которые ведёт бот (`match`, `botKey`, `description`, `sizeTable`, `sizeHW`, `photos`, `chart`,
`availability`), кабинет не показывает и не меняет — переносит как есть; у новой модели они пустые
(`match: []`, описание из `null`, `photos: []`, `chart: null`, `availability: { inStock: true, outSizes: [] }`).

| Поле | Тип | Смысл |
|---|---|---|
| `id` | slug | id товара: из названия латиницей при создании («Широкие трубы» → `shirokie-truby`), **не меняется никогда**. На него ссылаются поставки, остатки, заказы, объявления |
| `name` | string | «Джинсы Клёш». Уникально без учёта регистра. Переименование ничего не ломает |
| `categoryId` | string | id категории |
| `batches` | `Batch[]` | Все поставки модели, включая отменённые |
| `sizes` | `SizeStock[]` | Размеры модели с остатками и джинсами с заказами. **Порядок массива = порядок на экране** |
| `thresholds?` | `{ lowMax, midMax }` | Свои пороги модели. Нет — берутся пороги категории |
| `hiddenSizes?` | string[] | Скрытые размеры |
| `archived?` | boolean | В архиве |
| `code?` | string | Код на бирке: 1–4 заглавные буквы или цифры, «КЛ». Печатается после номера заказа (`N033529-КЛ`), чтобы сразу было видно, какую модель класть. Уникален среди всех моделей, в том числе архивных. Нет — номер без приписки |
| `packs?` | `Pack[]` | Пачки модели: `{ id, name, sizes }`. Название уникально внутри модели, в составе от двух размеров |

### Категория (`Category`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | slug | id из названия при создании, не меняется |
| `name` | string | «Джинсы». Уникально без учёта регистра. Модели ссылаются на категорию **по id** (`categoryId`) — переименование их не трогает |
| `sizes` | string[] | Шаблон размеров в нужном порядке: новая модель категории получает их, поставка их подсказывает |
| `thresholds` | `{ lowMax, midMax }` | Пороги для моделей категории без своих порогов. По умолчанию 5 / 10 |

### Отображение (`DisplaySettings`)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `showZeroOnTiles` | да | Показывать на плитках размеры с нулём |
| `showIncoming` | да | Показывать «+N» возвратов в пути |
| `tileRows` | 2 | Рядов чипов на плитке (2 или 3, по 3 в ряд) |

### Запись истории настроек (`SettingsLogEntry`)

`{ id, at, source, text }` — когда и что поменяли в настройках, текстом: ««Джинсы Клёш»: пороги 5 / 10 → 10 / 15».
История общая с ботом (`log.json`): кабинет пишет `source: "hub"`, записи бота в истории склада начинаются с «Бот:».
Новые сверху, хранится до 2000 записей.

### Размер (`SizeStock`)

| Поле | Тип | Смысл |
|---|---|---|
| `size` | string | «30» — номер размера. В `stock.json` размер — ключ: `products[productId][size] = { stock, units }`; пустой размер (ничего на полке и без заказов) там не хранится |
| `stock` | `{ batchId, qty }[]` | Сколько штук **на полке** из каждой поставки. Нулевых записей не держим |
| `units` | `Unit[]` | Джинсы этого размера, у которых есть заказ |

### Поставка (`Batch`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | Внутренний id |
| `productId` | string | Модель (товар), которой пришла поставка |
| `name` | string | «Клёш 14.11», при повторе «Клёш 14.11 (2)». Уникально внутри модели |
| `date` | `YYYY-MM-DD` | Дата прихода |
| `from` | string | Откуда: «Садовод», «Южные ворота» |
| `total` | number | Сколько заплатили за всю поставку, ₽. Больше нуля. Вписывается руками |
| `price` | number | Цена за штуку = `total` / штук, до копеек. Считается, руками не вводится |
| `delivered` | `{ size, qty }[]` | Сколько каких размеров пришло. Не меняется после добавления |
| `addedAt` | ISO | Когда внесли в систему (сортировка истории) |
| `cancelledAt?` | ISO | Когда отменили. Есть — поставка отменена |
| `packs?` | `{ name, count }[]` | Сколько каких пачек было — только для истории. Штуки из них уже в `delivered` |

### Джинса с заказом (`Unit`)

| Поле | Тип | Смысл |
|---|---|---|
| `order` | string | Номер заказа — номер сделки Авито |
| `orderDate` | string | Дата заказа, ДД.ММ |
| `status` | `UnitStatus` | См. раздел 4 |
| `batchId` | string | Из какой поставки взяли (отсюда закупка) |
| `pickupPoint?` | string | ПВЗ. У резерва нет |

### Черновик поставки (`DeliveryDraft`)

`{ id, updatedAt, date, dateSet?, from, lines: DeliveryLine[] }`. `dateSet` — дату выбрали руками; нет — при «Продолжить» встаёт сегодняшняя. Строка `DeliveryLine` — одна модель в окне поставки:
- `productId` — выбранная модель; `null` для новой, тогда заполнено `newProduct: { name, categoryId, categoryName? }`:
  категория выбрана из заведённых — `categoryId`; вписали новую — `categoryId: null` и `categoryName`, такая
  категория заведётся вместе с поставкой;
- `total` — сумма за поставку строкой, как в поле ввода;
- `step` — шаг кнопок −/+ (1, 2, 5, 10 или своё);
- `sizes` — размеры в карточке;
- `qty` — `{ [size]: количество }` — **отдельные** штуки, сверх пачек;
- `packs?` — пачки в карточке: `{ id, name, sizes, count, fresh? }`. `count` — сколько пачек пришло,
  `fresh` — собрана в этой поставке (сохранится у модели при добавлении). Нет поля — старый черновик, пачек нет.

Всего в размер приходит **отдельные + пачки**: `qty[size]` + сумма `count` пачек, в которых есть этот размер.

### Хранение

Склад — четыре файла сервера данных avito (формат — [avito/data/schema/FORMAT.md](../../data/schema/FORMAT.md)):

| Файл | Что | Хранилище |
|---|---|---|
| `catalog.json` | шкала размеров `sizeScale`, категории, товары (поля модели без поставок и остатков; поля бота) | `catalogStore` |
| `stock.json` | поставки `batches` (с `productId`) и остатки `products[productId][size] = { stock, units }` | `stockFileStore` |
| `hub.json` | отображение `display`, черновики `drafts` | `hubStore` |
| `log.json` | общая история `entries` | `logStore` |

Экранам и сверке заказов удобнее модель целиком, поэтому `shared/stock/store.ts` (`stockStore`, `useStock()`)
склеивает файлы в `{ models, categories, sizeScale, drafts, display, log }` при чтении и разбирает обратно при
записи. Действия экрана склада — `features/stock/store.ts`, хук `useStockStore()`.
- Пишется только поменявшийся файл: переименование трогает только `catalog` (и `log`), поставка — `catalog`
  (если появился размер или модель) и `stock`. Каталог уходит на сервер первым — на него ссылаются остатки.
- Каталог общий с ботом: кабинет не трогает поля бота и неизвестные поля, модель с данными бота нельзя удалить
  (только в архив), размер, на который есть строка размерной сетки бота, — тоже нельзя удалить. Архивные модели
  остаются в каталоге (бот считает их «нет в наличии»).
- Новые размеры попадают в шкалу `sizeScale` без буквы на своё место по номеру; буквы ведёт приложение бота.
- Пусто → пустой склад: ни моделей, ни категорий, ни поставок; отображение по умолчанию.
- Очистить: Настройки кабинета → «Данные» → «Очистить все данные» (SETTINGS.md, 5а). Модели с данными бота при
  этом остаются в каталоге — без поставок, остатков и полей кабинета.
- Формат меняется только вместе с FORMAT.md (версия файла, миграция). Старые ключи браузера (`hubbro.stock.v5` и
  раньше) больше не читаются и при запуске удаляются; перевести старые данные — `avito/data/schema/migrate-legacy.mjs`.
- Синхронизация с сервером — [ARCHITECTURE.md](ARCHITECTURE.md), «Сервер и данные».

## 3. Правила (не нарушать)

1. **Одна поставка = одна модель.** В одном окне можно оформить несколько моделей, но каждая сохраняется
   отдельной поставкой.
2. **Сумма поставки обязательна** и больше нуля. Цена за штуку не вводится, а считается: сумма ÷ штуки
   (до копеек). Закупка у каждой джинсы из поставки — эта цена за штуку.
3. **В поставке хотя бы одна штука.** Размеры с нулём не сохраняются.
4. **Остаток не правится руками как число.** Меняется только через движения: приход, отмена поставки,
   резерв, возврат, списание, корректировка (раздел 10).
5. **На полке не бывает меньше нуля.**
6. **В резерв берётся джинса из самой старой поставки** (по дате) — так закупка у заказа честная.
7. **`delivered` поставки не меняется.** Это факт прихода.
8. **Отмена поставки — только пока из неё ничего не ушло:** ни одной джинсы с заказом из неё и на полке
   ровно столько, сколько пришло. Иначе только корректировка.
9. **Отмена не удаляет запись** — ставит `cancelledAt`. История ничего не теряет.
10. **Название модели уникально** (без учёта регистра). Новую модель с существующим названием создать нельзя.
11. **Название поставки уникально внутри модели.**
12. **Проданные джинсы в интерфейсе не показываем** (история проданных — потом).
13. **Ничего с историей не удаляется — только в архив.** Удалить можно лишь то, у чего истории не было:
    модель — без единой поставки и заказа и без данных бота (описание, сетка, фото, слова); размер — которого
    никогда не было в поставках, на котором нет джинс и заказов и которого нет в размерной сетке бота;
    категорию — без моделей (в том числе архивных). Остальное: модель — в архив, размер — скрыть.
14. **Скрыть размер можно, только когда на нём 0 на полке и нет заказов.** Пришла поставка в скрытый размер —
    он сам снова показывается.
15. **Пороги: сначала модели, потом категории.** Есть свои у модели — берём их, нет — пороги категории,
    нет категории — 5 / 10. «Мало до» ≥ 1, «Норм до» больше «Мало до».
16. **Любое изменение настроек пишется в историю** одной строкой: что было и что стало.
17. **Название категории уникально.** Модели ссылаются на категорию по id — переименование меняет только название.
21. **Связи только по id.** Поставка, остатки, заказ, объявление ссылаются на модель по `id` товара, модель на
    категорию — по `categoryId`. Названия — для людей, их можно менять без последствий.
22. **Размер — номер.** Ввести в кабинете можно только номер («35»); буква берётся из шкалы магазина.
18. **Код на бирке — у модели и уникален среди моделей** — по нему на расклейке понимают, какую модель класть.
    У категории кода нет.
19. **В пачке по одной штуке каждого размера**, без исключений. Из пачки джинсы не убираются: штуки из пачек —
    минимум размера в поставке, `−` у размера убирает только отдельные штуки.
20. **Пачка — только для ввода.** На полке, в резерве и в отмене поставки пачек нет: при добавлении пачки
    раскладываются в `delivered` по размерам. Удаление или переименование пачки не трогает склад и историю.

## 4. Жизненный путь джинсы

```
На полке ──заказ──► В резерве ──► Отправлена ──► Доставлена (в ПВЗ) ──► Продана (скрыта)
                                                       │
                                       Возврат едет ◄──┘
                                            │
                                  Возврат на складе (нужно разобрать)
                                            │
                                  ├─► На полку
                                  └─► Брак (списание)
```

| `UnitStatus` | Подпись | Цвет | Где виден в размере |
|---|---|---|---|
| — | На складе | зелёный | всегда (строкой на поставку) |
| `reserve` | В резерве | жёлтый | сразу |
| `returnStock` | Возврат на складе · нужно разобрать | красный | сразу — ждёт действия |
| `sent` | Отправлена | жёлтый | под «Показать всё» |
| `delivered` | Доставлена · лежит в ПВЗ | зелёный | под «Показать всё» |
| `returnTransit` | Возврат едет · едет обратно | жёлтый | под «Показать всё» |

Цвет — подсказка, статус всегда подписан текстом (`StatusBadge`).
Резерв и снятие резерва уже ставит сверка заказов (`shared/fulfillment/reserve.ts`), в том числе когда у заказа
поменяли или убрали размер: старый резерв возвращается на полку своей поставки, берётся новый; отправка и возвраты
придут из заказов позже.
Статус заказа главный, статус джинсы выводится из него: какое событие заказа какое движение склада даёт —
[ORDERS.md](ORDERS.md), раздел 7.

## 5. Как считаются цифры

`stock.ts`, `delivery.ts`.

- **Остаток размера** `onHand` = сумма `stock[].qty`. Только то, что на полке.
- **Едет к нам** `incoming` = число джинс в статусе `returnTransit`. Показывается мелко: `5 +1`.
- **Уровень остатка** `stockLevel(qty, пороги)`:
  `0` → нет (серый зачёркнутый) · `≤ мало до` → мало (красный) · `≤ норм до` → норм (жёлтый) · больше → много (зелёный).
- **Пороги модели** `resolveThresholds`: свои → категории → `DEFAULT_THRESHOLDS` (5 / 10). На экран попадают
  через `StockSettingsContext` (`settings.ts`), чтобы не пробрасывать через все компоненты.
- **Видимые размеры** `visibleSizes`: размеры модели в её порядке без скрытых.
- **Порядок размеров** — как настроен у модели (перетаскиванием). «Выстроить по порядку» — `compareSizes`:
  по числу, потом по букве `XS < S < M < L < XL < XXL` (30S, 30M, 31S… и S, M, L, XL). Новые размеры
  встают в конец.
- **Порядок чипов «по срочности»** `sizesByAttention`: только видимые размеры, нет → мало → норм → много,
  внутри по количеству, потом по размеру.
- **Порядок плиток** `modelsByAttention`: всегда авто — по самому срочному размеру модели (с её порогами),
  при равенстве — у кого больше размеров «нет» и «мало».
- **Стоимость остатка** в строке «На складе» = штуки на полке × цена за штуку поставки, до копеек.
- **Цена за штуку** `unitPrice` = сумма поставки ÷ штуки, до копеек. Рубли показываются до копеек, только если они есть.
- **История** — поставки (по `addedAt`) и изменения настроек (по `at`) вместе, свежие сверху.
- **Модель видна в сетке и в поставке** `isModelVisible`: не в архиве и не «пустышка», у которой все поставки
  отменены. Новая модель без поставок (заведена в настройках) видна с нулями.

## 6. Экран «Остатки»

Шапка: «Склад», справа кнопки **«+ Поставка»**, **«История»** и **«⚙ Настройки»**. Открытая вкладка подсвечена
чёрным; повторный клик по ней или «← К остаткам» возвращает на остатки.
Под шапкой легенда цветов (без чисел — пороги у каждой категории и модели свои).

**Пустой склад** (моделей нет): вместо легенды и плиток карточка «Склад пуст — начните с модели» — что сделать
первым: «+ Поставка» → «+ Новая модель» (модель и категория заведутся вместе с первыми джинсами) или модель без
поставки в настройках склада (сначала категория, потом модель); потом подключить Авито и привязать объявления.
Кнопки «+ Поставка» и «Завести модель в настройках».

**Бенто-сетка плиток.** Одна общая сетка, без деления на категории. Фильтр `Все · Джинсы · Куртки`
появится, когда моделей станет больше ~10.

**Плитка модели:** название, категория, под ней «9 объявлений» (сколько объявлений Авито привязано, если есть
хоть одно), 2 или 3 ряда чипов (по 3 в ряд, настройка «Отображение») по срочности.
Размеры с нулём на плитке можно выключить там же. Не влезает —
последний чип «+N»: клик открывает модель (если уже открыта — не закрывает) и плавно прокручивает к её размерам.
- Клик по плитке — открыть или закрыть модель.
- Клик по чипу — открыть модель **и сразу этот размер**: раскрыть, прокрутить к нему и подсветить.

**Чип размера:** `31 5 +1` — размер, остаток (цвет по порогам модели), возвраты в пути (можно выключить). На плитке —
только номер размера, в строке размера — с буквой из шкалы: `31 (M) 5 +1`.

**Раскрытая модель** (под сеткой):
- шапка с названием, всеми чипами (тоже кликабельны) и «Свернуть»;
- видимые размеры в порядке модели (нули видны всегда). Строка размера: чип, стрелка, сводка «1 в резерве · 1 возврат разобрать».

**Раскрытый размер:**
```
31 (M)  5 +1
 ├─ 3 шт. · На складе · «Клёш 02.11» · 4 350 ₽ · 1 450 ₽ за шт.   ← строка на каждую поставку, количество первым
 ├─ 2 шт. · На складе · «Клёш 12.11» · 2 800 ₽ · 1 400 ₽ за шт.
 ├─ В резерве · заказ №1234 · «Клёш 02.11»         ← строка на каждую джинсу с заказом
 ├─ Возврат на складе · заказ №1198 · нужно разобрать
 └─ Показать всё (3) ▾
      ├─ Отправлена · заказ №1229
      ├─ Доставлена · заказ №1221 · лежит в ПВЗ
      └─ Возврат едет · заказ №1210
```
В строке «На складе» две суммы: сначала **стоимость остатка** этой поставки (штуки × цена за штуку, жирным),
потом **цена за штуку**.

Строка с заказом раскрывается: товар и размер, заказ и дата, ПВЗ, поставка и откуда, закупка.

**Анимации:**
- всё раскрывается плавно (`shared/ui/Collapse`, скорость — токен `--motion-expand`);
- при смене модели старая затухает, новая проявляется;
- место под полосу прокрутки зарезервировано (`scrollbar-gutter: stable`), чтобы раскладка не прыгала.

## 7. «+ Поставка»

Окно выезжает справа (`DeliveryDialog/`).

1. **Черновики** — если есть и окно пустое: список с «Продолжить» и «Удалить».
2. **Дата прихода** (по умолчанию всегда сегодня, в том числе в продолженном черновике, если дату в нём не меняли руками — `dateSet`) и **Откуда** (прошлые поставщики подсказываются).
3. **Выбор модели** — блок «Какая модель пришла?» / «Добавить ещё модель» **всегда наверху**, сразу под датой.
   Кнопки всех видимых моделей (архивные не показываются) и «+ Новая модель», уже выбранные пропадают. **Новая карточка появляется сверху**,
   уже заполненные уходят ниже: наверху всегда та модель, которую сейчас заполняешь.
4. **Карточка модели** (`DeliveryLineCard/`):
   - для новой модели — название и категория (существующие категории подсказываются);
   - **сумма поставки**, под ней «≈ 1 350 ₽ за шт.» (считается сама);
   - **шаг −/+**: 1, 2, 5, 10 или своё число — на столько прибавляют и убавляют кнопки;
   - **«Очистить»** — круглая кнопка с корзиной сразу после шага. Спрашивает «Вы уверены?» (Да / Нет);
     «Да» обнуляет сумму, шаг, пачки и все количества карточки; модель, список размеров и сами пачки остаются.
     Неактивна, пока в карточке нечего очищать;
   - сетка размеров: `−` / число / `+`, размер с количеством подсвечивается зелёным. В сетке видимые размеры
     модели в её порядке; у новой можно взять размеры из шаблона категории («Все» или по одному);
   - «+ Размер» — новый размер (приводится к верхнему регистру, повторы не добавляются);
   - **пачки** (`packs`):
     - пока у модели нет пачек, под «≈ N ₽ за шт.» кнопка **«Собрать пачку»** (видна, когда в карточке есть
       размеры). Открывает форму: название (уникальное в модели) и размеры карточки чипами, сразу все отмечены,
       нужно хотя бы два. «Собрать» / «Отмена»;
     - пачки есть — над сеткой размеров заголовок **«Пачки»** и «+ Добавить» (та же форма), ниже плашка на каждую
       пачку во всю ширину: «Пачка · Стандарт», под ним состав «28S · 29S · …», справа `−` / число / `+` с шагом
       карточки, число можно вписать. Это **сколько пачек пришло**: +1 пачка = +1 в каждый её размер;
     - пачки модели появляются в карточке сами, по нулям. Размер пачки, скрытый у модели, возвращается в сетку,
       как только пачка больше нуля;
   - в ячейке размера, где есть штуки из пачек, вместо серого `0` стоит **серое число из пачек** (минимум),
     `−` неактивен. Прибавили отдельно — серое число остаётся, рядом чёрным `+1`; `−` и ввод руками меняют только
     отдельные штуки. Длинное число («18 +120») не обрезается — шрифт мельчает, чтобы всё влезло. Ячейка зелёная,
     если в размере есть хоть одна штука;
   - итог: штуки (пачки + отдельные), сумма, цена за штуку. Крестик убирает модель из поставки.
5. **«Продолжить»** активна, только когда всё заполнено. Иначе внизу первая причина:
   - «Укажите, откуда поставка»;
   - «Впишите название модели», «Такая модель уже есть, выберите её из списка»,
     «Такая модель есть в архиве — верните её в настройках склада», «Укажите категорию»;
   - «Впишите сумму поставки», «Добавьте хотя бы одну штуку»;
   - «Одна модель выбрана дважды», «Две новые модели с одинаковым названием».
6. **«Проверьте поставку»**: для каждой модели — название будущей поставки, цена за штуку, размеры (с пачками),
   «Из них пачки: «Стандарт» × 3», штуки и сумма;
   предупреждения о дублях; общий итог. Кнопки «Назад, исправить» и «Добавить на склад».
7. **Добавление** (`applyDelivery`). Для каждой строки:
   - если модель новая — создаётся модель;
   - создаётся поставка с уникальным названием, `delivered` из ненулевых размеров (пачки + отдельные), `total` из суммы,
     `price` = `total` ÷ штуки, `packs` — пачки больше нуля;
   - собранные в этой поставке пачки (`fresh`) сохраняются у модели, даже если их не использовали;
   - в каждый размер добавляется запись `stock` этой поставки (размера нет — создаётся, встаёт в конец);
   - скрытые размеры, в которые пришли джинсы, снова показываются;
   - новой категории (вписали в «+ Новая модель») создаётся категория с размерами модели и порогами 5 / 10.

   Черновик, из которого добавляли, удаляется. Всплывает «Поставка добавлена: N шт.».

### Защита от дублей

- **Двойное нажатие:** «Добавить на склад» срабатывает один раз. С бэкендом — одноразовый ключ формы.
- **Та же модель на ту же дату уже есть:** на проверке жёлтое «Уже есть поставка». Если совпадают и размеры
  с количествами — красное «Похоже на дубль». Добавить всё равно можно: бывает докупка в тот же день.
- **Повтор названия** → «(2)», «(3)».
- **Импорт из файла (потом):** отпечаток файла, тот же файл второй раз не загрузится.

### Черновики

- «Сохранить черновик» — в любой момент, когда выбрана хоть одна модель и есть изменения.
- Закрытие (крестик, фон, Esc) с несохранёнными изменениями → «Закрыть без сохранения?»:
  «Сохранить черновик» / «Не сохранять» / «Остаться».

## 8. История и отмена поставки

`HistoryView/`. Поставки и изменения настроек вместе, свежие сверху. Сверху фильтр `Всё · Поставки · Настройки`.

Изменение настроек — компактная строка: дата и время, метка «Настройки», текст (««Куртка Дутая» убрана в архив»).

Карточка поставки:
- дата, «Поставка · модель»;
- название поставки, откуда, цена за штуку;
- размеры × количество;
- «Из них пачки: «Стандарт» × 3», если были пачки;
- «+N шт. на сумму поставки».

**Отмена:**
- «Отменить поставку» → подтверждение прямо в карточке → `cancelDelivery`:
  - убирает записи `stock` этой поставки;
  - ставит `cancelledAt`;
  - удаляет размеры, которые появились только с этой поставкой и остались пустыми.

  Карточка остаётся с пометкой «Отменена DD.MM».
- Если отменить нельзя (`canCancel` = false), вместо кнопки надпись «Из поставки уже есть заказы — отменить нельзя».
- Модель без живых поставок и заказов (например, новая модель, чью единственную поставку отменили) пропадает
  из сетки, но в истории остаётся.

## 9. Настройки склада

Кнопка «⚙ Настройки» в шапке (`SettingsView/`). Три раздела: `Модели · Категории · Отображение`.
**Права доступа пока не проверяются** — менять может любой. Потом раздел закроем правами.
Каждое изменение сохраняется сразу (поля — когда ушёл из поля или нажал Enter), всплывает «Сохранено»,
в историю пишется строка.

### Модели (`ModelSettingsCard/`)

Категорий ещё нет — вместо формы подсказка «Модель всегда в категории… Сначала заведите категорию» и кнопка
«Завести категорию» (открывает раздел «Категории»).
Сверху форма «Новая модель»: название + категория → «+ Модель». Модель получает размеры из шаблона категории,
поставок у неё нет, на складе видна с нулями.

Модели сгруппированы по категориям, архив — отдельной свёрнутой группой «Архив (N)». Карточка раскрывается:
- **название** — уникальное;
- **категория** — выбор из существующих;
- **код на бирке** — рядом с категорией: буквы сами становятся заглавными, лишнее отсекается (до 4 знаков); занят
  другой моделью — «Такой код уже у другой модели». Сохраняется, когда уходишь из поля. В шапке карточки код стоит
  первым;
- **пороги**: «Как у категории (5 / 10)» или «Свои для этой модели» + поля «Мало — до», «Норм — до»
  и живой пример чипов (`ThresholdEditor/`);
- **размеры** (`SizeListEditor/`): перетаскивание для своего порядка, «Выстроить по порядку», «+ Размер»,
  глаз — скрыть / показать (неактивен, если на размере есть джинсы или заказы), ✕ — удалить (только если
  размера никогда не было в поставках);
- **пачки** (если есть): название (переименовать, уникальное) и состав подписью, «Удалить» с подтверждением.
  Состав не правится — собрать новую в поставке. Удалённый размер уходит и из пачек; пачка меньше чем из двух
  размеров удаляется;
- **объявления на Авито** (`ModelListings/`): привязанные объявления — название (ссылка на Авито), цена, статус, ID
  и крестик «Отвязать» (сразу, без подтверждения, строка в историю). В шапке карточки — «· 9 объявлений».
  Привязывают на странице «Объявления» ([LISTINGS.md](LISTINGS.md));
- **«В архив» / «Вернуть из архива»**; «Удалить» — только у модели без поставок и заказов, с подтверждением.
  Удалённая модель отвязывает свои объявления — они становятся «без товара».

### Категории (`CategorySettingsCard/`)

Форма «Новая категория». Карточка категории:
- **название** (уникальное, переименование меняет категорию и у моделей);
- **пороги для моделей категории** — действуют на модели без своих порогов (видно, у скольких свои);
- **шаблон размеров** — порядок, добавить, убрать. На уже заведённые модели не влияет;
- **«Удалить категорию»** — только пустую.

### Отображение (`DisplaySettingsPanel/`)

Переключатели «Размеры с нулём на плитках», «+N — возвраты, которые едут к нам» и «Рядов чипов на плитке: 2 / 3».
Порядок плиток не настраивается — всегда по срочности.

## 10. Журнал движений

Цель: каждое изменение остатка — запись (что, сколько, по какой поставке, когда, почему). Сейчас роль журнала
играют поставки (`delivered`, `cancelledAt`) и статусы джинс. Отдельная таблица движений появится вместе
с бэкендом.

| Движение | На полке | Откуда | Статус |
|---|---|---|---|
| Приход | + | «+ Поставка» | сделано |
| Отмена поставки | − | История | сделано |
| Резерв | − | Сверка заказов: размер есть, самая старая поставка | сделано |
| Снятие резерва | + | Сверка заказов: заказ отменили до отправки, поменяли размер или товар (перепривязали объявление) | сделано |
| Возврат разобран | + | «Возврат на складе» → «На полку» | позже |
| Брак / списание | уходит из учёта | Возврат → «Брак» или списание с полки | позже |
| Корректировка | + / − | Пересчитали руками | позже |

### Корректировка остатков (позже)

- В строке «N шт. · На складе · поставка» кнопка «Поправить».
- Фактическое количество или ±, видно «было 5 → станет 4».
- Причина обязательна: пересчёт, брак, потеря, нашлось, другое (+ комментарий).
- Меньше нуля нельзя. Резерв корректировкой не трогается.
- Потом — «Пересчёт модели»: фактические остатки по всем размерам разом, расхождения записываются пачкой.
