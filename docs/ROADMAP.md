# HUB BRO — логика и roadmap

Проект пересобирается с нуля. Здесь зафиксировано, о чём договорились, и где мы сейчас.

## Как работает

```
Авито: оплаченная сделка (объявление + покупатель)
        │
        ├─ размер уже пришёл от бота ──► ГОТОВ ──► склад: есть модель+цвет+размер?
        │                                           ├─ да  → резерв → очередь печати
        │                                           └─ нет → «Проблемы: нет на складе»
        │
        └─ размера нет ──► просим бота Гришки спросить
                           └─► «Проблемы: без размера», пока не ответит
```

1. **Сделка.** Заказы забираем из кабинета Авито расширением Chrome (API заказов закрыт без Доставки для бизнеса):
   номер, объявление, служба доставки, номер отправления, срок отгрузки, статус, чат, деньги. Адрес ПВЗ не берём.
   Подробно — [EXTENSION.md](EXTENSION.md).
2. **Размер.** Пока бота Гришки нет — руками в комплектации или в заказе. Потом бот вытаскивает размер из чата
   Авито; чат и заказ связаны по id чата.
   - Размер есть → заказ готов и уходит на склад.
   - Размера нет → командуем боту спросить; заказ висит в «Проблемах» с пометкой «без размера» и в очередь печати не попадает.
3. **Сопоставление.** Объявление = одна модель одного цвета, размер — из чата. Модель + цвет + размер = позиция на складе. Всё на складе считаем уже упакованным и лежащим на своей полке.
   - Есть → резерв, заказ в очередь «к печати».
   - Нет → «Проблемы: нет на складе».
4. **Печать.** Комплектация собирает очередь (порядок и фильтры настраиваются) и отправляет партии на пульт;
   пульт печатает и отмечает «Партия расклеена» — заказ становится «Собран». Подробно — [PICKING.md](PICKING.md). Печатаем **свою бирку** на Xprinter 365B, не транспортную этикетку Авито. Бирка 40×58 в двух раскладках (с названием товара и без):
   логотип, `N` + 6 последних цифр номера Авито + код категории (`N033529-КЛ`), размер, **Code128 с номером
   отправления** (его пикают в ПВЗ), служба — [SETTINGS.md](SETTINGS.md), «Бирка».
5. **Заказы.** Все заказы из Авито со статусами (Заказан → Собран → Отправлен → … → Завершён, плюс Отменён и ветка возврата), фильтры по датам, карточка с историей. С первого дня храним каждую смену статуса с датой. Подробно — [ORDERS.md](ORDERS.md).

## Решения

| Тема | Решение |
|------|---------|
| Связь с ботом Гришки | Бот отдаёт размер в Telegram, наш Telegram-бот пробрасывает его вебхуком к нам. Команда «спроси размер» идёт тем же путём. |
| Формат сообщений бота | Строгий, машиночитаемый, например `SIZE item=… user=… size=L` и `ASK item=… user=…` |
| Объявление | Одна модель одного цвета, размер выбирается в чате |
| Начальные остатки | Ручной ввод и импорт CSV / Excel / Google-таблицы (как CSV по ссылке) |
| Нет ответа о размере | Заказ помечается «без размера» и считается проблемой, пока размер не получен |
| Что печатаем | Только свою бирку на товар |
| Откуда заказы | Кабинет Авито через расширение Chrome, пока нет Доставки для бизнеса ([EXTENSION.md](EXTENSION.md)) |
| Штрихкод бирки | Code128 с номером отправления — тот же, что Авито показывает для сдачи в ПВЗ |
| Номер на бирке | `N` + 6 последних цифр номера заказа Авито + код категории (`N033529-КЛ`) |
| Размер, пока нет бота | Руками: в «Проблемах» комплектации или в раскрытом заказе, с подтверждением |
| Номер заказа | Номер Авито, свой не заводим |
| Заказ | Одна сделка = одна джинса |
| Проблемы | Пометка на заказе в «Заказан» (без размера, нет на складе), не отдельный статус |
| Статусы заказа | См. [ORDERS.md](ORDERS.md) |
| Дизайн | См. [DESIGN.md](DESIGN.md) |

## Риски

- **Боты в Telegram по умолчанию не видят сообщения других ботов.** Схему «бот Гришки пишет → наш бот читает» надо проверить первой. Запасной вариант — бот Гришки шлёт HTTP-запрос прямо на наш адрес.
- **API заказов Авито отвечает 403**, пока не подключена Доставка для бизнеса (реквизиты ИП/ООО + тариф);
  перепроверено 16.11.2026. Обходим расширением, которое читает внутренний JSON кабинета Авито
  ([ORDERS.md](ORDERS.md), раздел 2; [EXTENSION.md](EXTENSION.md)).
- **Внутренний API Авито** может поменяться без предупреждения, а частые запросы он режет (429). Расширение
  запрашивает только по кнопке, карточки открывает только у ждущих отправки и замедляется после 429. Когда будет
  ИП и Доставка для бизнеса — переходим на официальный API.

## Открытые вопросы

1. Словарь размеров: только S/M/L/XL или бывают 28/30, «W30 L32».
2. Сколько ждать ответа о размере до напоминания.
3. Стек бэкенда. Пока — Vercel: функция `/api/state` и Upstash Redis (ARCHITECTURE.md, «Сервер»).
4. Когда оформляем ИП и Доставку для бизнеса — тогда заказы из официального API вместо расширения.

Решено 16.11.2026: в штрихкоде бирки — номер отправления; номер на бирке — хвост номера Авито.

## Этапы

0. **Договорённости.** Формат обмена с ботом Гришки, штрихкод, словарь размеров, стек.
1. **Склад.** Модели, размеры, партии, остатки, импорт, привязка «объявление → модель» (сделано, [LISTINGS.md](LISTINGS.md)). Решения — [WAREHOUSE.md](WAREHOUSE.md).
2. **Приём заказов.** Заказы из кабинета Авито через расширение — сделано (без дублей, статусы, деньги); размер
   пока руками; привязка объявлений к моделям склада — сделана, осталось брать по ней товар заказа; дальше бот Гришки.
3. **Сопоставление и очередь печати.** Сделано на тестовых данных: сверка со складом, комплектация, пульт.
   Порядок очереди один и автоматический: категория → товар → размер → служба, срочные сверху ([PICKING.md](PICKING.md)).
4. **Печать бирок.** Генератор бирки и печать с пульта на Xprinter.
5. **Раздел «Заказы».** Статусы, фильтры по датам, карточка с историей. Решения — [ORDERS.md](ORDERS.md).
6. **Живые подключения.** Официальный API Авито (после ИП), бот Гришки, Xprinter на складе.
7. *Будущее:* полноценная CRM или выгрузка во внешнюю.

Этапы 1, 3 и 4 не зависят от Гришки и Авито.
