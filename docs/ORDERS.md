# Заказы — полная документация

Единственный источник правды по заказам HUB BRO: откуда приходит заказ, что хранится, какие бывают статусы и кто
их меняет, какие правила нельзя нарушать, как заказ связан со складом, комплектацией и расклейкой, как работает
экран.

**Как пользоваться документом:**
- перед любой работой с заказами (`web/src/shared/orders/`, `web/src/features/orders/`, а также комплектация,
  пульт и склад там, где они читают или меняют заказ) читай его;
- после любого изменения заказов (логика, данные, статусы, экраны, тексты) обнови нужные разделы и журнал
  изменений внизу в том же коммите;
- если изменение задевает склад — обнови и [WAREHOUSE.md](WAREHOUSE.md): связь описана в обоих документах.

Код: общее хранилище заказов — `web/src/shared/orders/` (заказы читают и меняют несколько разделов, а разделы
друг друга не импортируют), партии печати и сверка со складом — `web/src/shared/fulfillment/`, экраны —
`web/src/features/orders/`, `features/picking/` (комплектация), `features/labels/` (пульт). Бэкенда нет, API
заказов Авито отвечает 403 (не подключена Доставка для бизнеса) — заказы приходят из кабинета Авито через
расширение Chrome ([EXTENSION.md](EXTENSION.md)); до первого приёма в кабинете тестовые данные.

## 1. Словарь

| Термин | Что это |
|---|---|
| **Заказ** | Оплаченная сделка Авито с доставкой. **Один заказ = одна джинса.** |
| **Номер заказа** | Номер сделки Авито. Своих номеров не заводим. |
| **Объявление** | Одна модель одного цвета на Авито. У модели может быть много объявлений с разными названиями. Привязано к модели склада по ID Авито ([LISTINGS.md](LISTINGS.md)), поэтому заказ знает товар. |
| **Размер** | Подпись как на складе («31M», «XL»). Не из Авито: из чата с покупателем — пока руками в комплектации, потом от бота Гришки. |
| **Номер отправления** | Номер посылки у службы. Его штрихкод (Code128) пикают в ПВЗ; он же на бирке. Из кабинета Авито. |
| **Статус** | Где сейчас заказ: Заказан → Собран → … (раздел 5). Один в момент времени. |
| **История статусов** | Все смены статуса с датой и временем. Только дописывается. |
| **Проблема** | Пометка на заказе в «Заказан», которая мешает его собрать: «Без размера» или «Нет на складе». Не статус. |
| **Резерв** | Джинса на складе, закреплённая за заказом. С этого момента она уникальная (см. WAREHOUSE.md). |
| **Бирка** | Наша наклейка 80×50 на джинсу с номером заказа. Печатается на «Пульте». |
| **Служба доставки** | СДЭК, Авито, Почта, Яндекс, 5Post — куда сдаём посылку. Адрес ПВЗ не храним, только службу. |
| **Очередь печати** | Заказы в «Заказан» без проблем и не в партии: ждут, пока комплектация отправит их на пульт. |
| **Партия печати** | Заказы, которые комплектация одним махом отправила на пульт. Номер №1, №2… Не путать с поставкой склада. |
| **Этап комплектации** | Где заказ в комплектации: Проблема, К печати, В партии, Напечатан, Собран. Не статус — считается. |
| **Закрытый заказ** | В конечном статусе: Завершён, Отменён, На складе, Брак. Больше не меняется. |
| **Активный заказ** | Любой не закрытый. |

## 2. Откуда что приходит

```
 Авито ─────────── сделка: номер, дата, объявление, служба, номер отправления, срок, чат, цена, покупатель
   │               статусы доставки: Отправлен, В доставке, Приехал, Завершён, Отменён, Возврат
   ▼
 ЗАКАЗ ◄────────── размер из чата: пока руками в комплектации, потом бот Гришки
   │
   ├──► Склад: есть модель + размер на полке? ── да → резерв ── нет → проблема «Нет на складе»
   │
   ├──► Комплектация: очередь печати ──► партия на пульт
   ├──► Пульт: напечатали, расклеили ──► «Партия расклеена» ──► статус «Собран»
   │
   └──► Разбор возврата: проверили ──► «На складе» (джинса на полку) или «Брак» (списание)
```

| Данные | Источник | Когда приходят |
|---|---|---|
| Номер, дата, объявление → товар, служба доставки, номер отправления, срок отгрузки, чат, цена, покупатель | кабинет Авито (раздел 2) | вместе со сделкой |
| Размер | пока руками в комплектации («Проблемы»); потом бот Гришки (через наш Telegram-бот, вебхуком) | позже сделки, иногда сильно позже |
| Статусы доставки и отмена | Авито | по мере движения посылки |
| Резерв / «нет на складе» | наш склад | как только у заказа есть размер |
| «Собран» | наш пульт | «Партия расклеена» |
| «Возврат на проверке», «На складе», «Брак» | наш разбор возврата | когда возврат приехал и его проверили |

Нет размера → заказ висит с пометкой «Без размера», размер выбирают руками в комплектации (раздел 6). Когда
подключим бота Гришки — просим его спросить в чате (команда `ASK item=… user=…`). Подробности обмена с ботом — [ROADMAP.md](ROADMAP.md).

### Что сейчас реально отдаёт API Авито (проверено 16.11.2026)

Аккаунт «BRO x BRO SHOP» продаёт через обычную Авито Доставку для частников. У неё нет API заказов.

| Что | Ответ | Что даёт |
|---|---|---|
| Заказы (`/order-management/1/orders`) | **403** «API работает только с Авито Доставкой для бизнеса» | — |
| Этикетки (`/order-management/1/orders/labels`) | не закрыт, но на наши заказы — «order not printable» | — |
| Чаты (messenger) | работает | системное «У вас новый заказ. Отправьте его через пункт СДЭК до 18 ноября»; из чата — объявление, цена, имя покупателя |
| Объявления, статистика | работает | название, цена, статус; просмотры, контакты, избранное по дням |
| Отзывы, баланс, история операций | работает | отзывы с текстом; траты на продвижение; номера заказов — только там, где начислялись бонусы |

**Чего нет без Доставки для бизнеса:** номера заказа, ПВЗ, статусов доставки, QR / штрихкода для сдачи в ПВЗ.
QR для сдачи при обычной доставке есть только в приложении Авито на странице заказа.

**Если подключить Доставку для бизнеса** (реквизиты ИП/ООО + тариф): откроется API заказов (номер, товар, ПВЗ,
статусы, сроки отгрузки) и этикетки PDF со штрихкодом, который сканирует ПВЗ.

**Без неё** факт заказа можно ловить по системному сообщению в чате: служба доставки + срок отгрузки + объявление
+ покупатель. Номера Авито там нет — а он у нас ключ заказа (правило 1).

### Заказы из кабинета Авито (найдено 16.11.2026, решение — расширение Chrome)

Всё, чего нет в API, есть на странице заказов кабинета `avito.ru/orders` под входом продавца. Страница грузит
внутренний JSON сайта:

| Запрос | Что берём |
|---|---|
| `/web/1/orders?page=1&limit=20` (страницы, `hasMore`) | `orderId` — номер заказа Авито (`70000000566033529`); `channelId` — id чата, тот же, что в API сообщений (по нему размер); `provider` — служба (`avito-pvz`, `pochta`, `cdek`, `yandex-market-pvz`) и трек; `status`; срок отгрузки; сумма; дата |
| `/web/2/profile/order?referenceID=<orderId>` | `itemId` — объявление → модель склада; `sellerDispatchNumber` — **номер отправления**; `sendBarcode` — штрихкод для ПВЗ; `sellerSendTill` |

- Штрихкод, который показывают в ПВЗ (в мобильной карточке заказа), — **Code128 с номером отправления**, у всех
  служб. Не QR и без скрытых данных: печатаем его сами на нашей бирке ([SETTINGS.md](SETTINGS.md), «Новая бирка»).
- Размера в заказе нет — он из чата.
- Адреса ПВЗ покупателя нет — храним только службу.

**Как ложится на наш заказ** (`shared/orders/avito.ts`):

| Служба Авито (`provider.value`) | У нас |
|---|---|
| `avito-pvz` | Авито |
| `pochta` | Почта |
| `cdek` | СДЭК |
| `yandex-market-pvz` | Яндекс |
| `5post` и всё, где в значении или названии есть «5post» / «5 Post» | 5Post (точное значение вживую не видели) |

| Статус Авито (`status.value`, подпись) | У нас |
|---|---|
| `confirmed` «Отправьте заказ», `waiting_confirmation` | Заказан |
| `performed` «Едет к покупателю» | В доставке |
| `provided` «Ждёт выдачи покупателю» | Приехал |
| `accepted` «Завершён» / «Получите оплату» | Завершён |
| `on_delivery_return` «Возврат: заберите заказ», `return_performed` «Возврат: едет к вам», `returned` «Закрыт после возврата» | Возврат (дальше — наш разбор возврата) |
| `canceled`, `canceled_by_buyer` «Отменён», `voided` | Отменён |
| `disputed` | статус не меняем, пометка «Спорный» (`disputed`) |

`applyAvitoStatus` применяет статус по правилам 6 и 11: закрытый заказ не трогаем; назад по пути не ходим
(у нас «Собран», а Авито ещё «Отправьте заказ» — остаётся «Собран»); шаг вперёд с пропуском принимаем
(«Едет к покупателю» у заказа в «Заказан»); повтор и незнакомый статус ничего не меняют. Значения сняты
с живых заказов 16.11.2026; `disputed` и `waiting_confirmation` вживую не видели. «Отправлен» отдельно Авито
не показывает — сразу «Едет к покупателю».
- **Расширение Chrome** (`extension/`) забирает список и карточки по кнопке — на странице Авито или «Подтянуть
  из Авито» на экране «Заказы» — и отдаёт кабинету; кабинет сливает по номеру без дублей (`mergeAvitoBatch`).
  Подробно — [EXTENSION.md](EXTENSION.md).
- Риск: это внутренний API сайта, Авито может поменять его без предупреждения — тогда чиним расширение.
  Когда появится ИП и Доставка для бизнеса, переходим на официальный API.

## 3. Что хранится

### Заказ (`Order`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | string | Номер сделки Авито, цифрами без пробелов. Он же ключ заказа |
| `createdAt` | string | Когда пришла оплаченная сделка, ISO. По нему период и группировка по дням |
| `product` | string | Товар. По нему склад ищет модель (точное совпадение с названием модели). У тестовых заказов — модель склада; у заказов из Авито пока **название объявления** — нужно брать модель по привязке `itemId` → «Объявления» ([LISTINGS.md](LISTINGS.md)) |
| `size?` | string | Размер из чата. Нет — бот ещё не прислал |
| `manualSize?` | `{ original? }` | Размер правили руками; `original` — какой был до первой правки (нет — размера не было) |
| `service` | `DeliveryService` | Служба доставки: `cdek` СДЭК · `avito` Авито · `post` Почта · `yandex` Яндекс · `fivepost` 5Post |
| `dispatchNumber?` | string | Номер отправления, без пробелов. Появляется после оформления |
| `shipBy?` | string | Отгрузить до, YYYY-MM-DD |
| `itemId?` | string | Id объявления Авито |
| `chatId?` | string | Id чата с покупателем (`u2i-…`) — ссылка «Чат с покупателем» |
| `syncedAt?` | string | Когда последний раз сверяли с Авито, ISO |
| `disputed?` | boolean | Авито пометил заказ спорным. Статус не меняется |
| `payout?` | number | Сколько получим — «Вы получите» у Авито (из списка, есть у каждого заказа). Видно в строке заказа |
| `price?` | number | За сколько продан товар после скидок Авито (из карточки) |
| `listPrice?` | number | Цена объявления до скидок (из карточки, `oldPrice`) |
| `buyer` | string | Покупатель. Храним, на экране пока не показываем |
| `status` | `OrderStatus` | Текущий статус = статус последней записи истории |
| `problem?` | `OrderProblem` | `noSize` / `noStock`. Только у статуса `ordered` |
| `history` | `StatusChange[]` | Все смены статуса по порядку, первая — `ordered` |

### Смена статуса (`StatusChange`)

| Поле | Тип | Что это |
|---|---|---|
| `status` | `OrderStatus` | Новый статус |
| `at` | string | Когда сменился, ISO |

### Статусы (`OrderStatus`)

`ordered` Заказан · `packed` Собран · `sent` Отправлен · `inTransit` В доставке · `arrived` Приехал ·
`completed` Завершён · `cancelled` Отменён · `returnTransit` Возврат · `returnCheck` Возврат на проверке ·
`returnStock` На складе · `defect` Брак.

Подписи и цвета — в `shared/orders/statuses.ts` (`STATUS_META`), больше нигде не дублируются.

## 4. Правила (не нарушать)

1. **Номер заказа — номер Авито.** Своих номеров не заводим, заказ ищется и показывается по нему.
2. **Один заказ — одна джинса.** Сделок на несколько пар пока не было; появятся — сначала правим этот документ.
3. **История только дописывается.** Каждая смена статуса — новая запись с датой и временем, старые не
   правятся и не удаляются. Храним с первого дня.
4. **`status` всегда равен последней записи `history`.** Менять статус можно только добавлением записи.
5. **Кто какой статус ставит — строго по таблице раздела 5.** Статусы Авито руками не ставим. Руками (с пульта
   и из разбора возврата, не с экрана заказов) ставятся только «Собран», «Возврат на проверке», «На складе», «Брак».
6. **Статусы Авито принимаем как пришли,** даже если какой-то шаг пропущен: записываем в историю, не блокируем.
   Наши статусы ставятся только по разрешённым переходам (раздел 5).
7. **Отменить можно только до отправки:** из «Заказан» или «Собран». Резерв снимается, джинса на полку.
8. **Проблема бывает только у заказа в «Заказан».** Заказ с проблемой не собирается и не печатается.
9. **«Собран» — только у заказа с размером и резервом.** Без резерва бирку не клеим.
10. **Резерв — из самой старой поставки** (правило 6 склада), чтобы закупка у заказа была честной.
11. **Закрытый заказ больше не меняется.** Завершён, Отменён, На складе, Брак — конечные.
12. **Экран заказов статусы не меняет.** Кнопок смены статуса на нём нет: статусы двигают Авито, пульт
    и разбор возврата. Единственное, что там правится, — размер (раздел 6).
13. **Этапы комплектации — не статусы.** «К печати», «В партии», «Напечатан» считаются из статуса, пометки и
    партий (раздел 7). Новых статусов заказа под них не заводим.
14. **«Собран» ставит только «Партия расклеена» на пульте** — и только заказам без ошибки, которые всё ещё
    «Заказан». Заказ с ошибкой (бирка не напечаталась, штрихкод не читается…) остаётся «Заказан» и снова в очереди.
15. **Партии не удаляются.** «Вернуть в очередь» ставит отметку, партия остаётся в истории пульта.

## 5. Жизненный путь заказа

```
Заказан ──► Собран ──► Отправлен ──► В доставке ──► Приехал ──► Завершён
   │           │                                      │
   └───────────┴──► Отменён                        Возврат
                                                      │
                                              Возврат на проверке
                                                      │
                                               ├─► На складе
                                               └─► Брак
```

| Статус | Кто ставит | Когда | Тон | Джинса на складе (`UnitStatus`) | Чип |
|---|---|---|---|---|---|
| Заказан | Авито | пришла оплаченная сделка | жёлтый | `reserve`, если есть размер и джинса | К сборке |
| Собран | **мы** — пульт | «Партия расклеена» | зелёный | `reserve` | Собран |
| Отправлен | Авито | сдали в ПВЗ | жёлтый | `sent` | В пути |
| В доставке | Авито | едет к покупателю | жёлтый | `sent` | В пути |
| Приехал | Авито | лежит в ПВЗ покупателя | зелёный | `delivered` | В ПВЗ |
| Завершён | Авито | покупатель забрал | серый | продана, скрыта | Закрытые |
| Отменён | Авито | отменили до отправки | серый | резерв снят, джинса на полке | Закрытые |
| Возврат | Авито | не забрал или вернул, едет к нам | жёлтый | `returnTransit` | Возвраты |
| Возврат на проверке | **мы** | возврат приехал, проверяем | красный | `returnStock` (нужно разобрать) | Возвраты |
| На складе | **мы** | проверили, целая | зелёный | +1 на полку той же поставки | Закрытые |
| Брак | **мы** | проверили, брак | серый | списание | Закрытые |

**Статус заказа — главный**, статус джинсы на складе выводится из него, а не наоборот.

### Разрешённые переходы

| Из | В | Кто |
|---|---|---|
| Заказан | Собран | мы (пульт, «Партия расклеена») |
| Заказан, Собран | Отменён | Авито |
| Собран | Отправлен | Авито |
| Отправлен | В доставке | Авито |
| В доставке | Приехал | Авито |
| Приехал | Завершён, Возврат | Авито |
| Возврат | Возврат на проверке | мы (приёмка возврата) |
| Возврат на проверке | На складе, Брак | мы (разбор) |

Остальные переходы для наших статусов запрещены. Для статусов Авито — правило 6.

## 6. Проблемы

| Пометка | Когда ставится | Когда снимается |
|---|---|---|
| Без размера (`noSize`) | заказ пришёл, а размера нет | выбрали размер в комплектации (или прислал бот) |
| Нет на складе (`noStock`) | размер есть, а модели + размера на полке нет | джинса появилась (поставка, возврат) и встала в резерв |

- **Размер руками** (`setOrderSize`), пока нет бота Гришки. Два места: «Проблемы» в комплектации (у «Без
  размера», рядом ссылка «к заказу →») и раскрытый заказ на экране «Заказы» (поставить или поменять). Чипы —
  размеры модели со склада с остатком на полке; клик выбирает, кнопка «Поставить 32S» / «Поменять 32S на 34L»
  сохраняет, «Отмена» сбрасывает. Только у «Заказан» и не в партии на пульте (бирка уже в работе — сначала
  вернуть партию в очередь). Поменяли размер у заказа с резервом — сверка снимает старый резерв (+1 на полку
  своей поставки) и ставит новый или «Нет на складе».
- **Вернуть исходный размер** (`resetOrderSize`): в раскрытом заказе, если размер правили руками, — ссылка
  «↺ Вернуть исходный размер (34L)» / «(не было)», тоже с подтверждением («Вернуть 34L» / «Убрать размер»).
  Исходный — тот, что был до первой ручной правки (`manualSize.original`). Не было — заказ снова «Без размера»,
  резерв снимается.
- Сначала «Без размера»: пока размера нет, проверять склад нечего. Пришёл размер — заказ сразу идёт на склад,
  и либо встаёт в резерв, либо получает «Нет на складе».
- Отменили заказ с проблемой — пометка уходит вместе с ним (статус Отменён проблем не имеет).
- На экране: красный бейдж «⚠ …» рядом со статусом и отдельный чип «Проблемы».

## 7. Связи с другими разделами

### Склад

Заказ двигает джинсы — каждое событие заказа = движение склада (журнал движений, WAREHOUSE.md раздел 10):

| Событие заказа | Движение склада | На полке |
|---|---|---|
| Пришёл размер, джинса есть (или «Собран» без резерва) | Резерв из самой старой поставки | −1 |
| Пришёл размер, джинсы нет | — (пометка «Нет на складе») | 0 |
| Отменён (из Заказан / Собран) | Снятие резерва | +1 |
| Поменяли размер у заказа с резервом | Снятие старого резерва, резерв нового размера | +1 / −1 |
| Отправлен … Приехал | Джинса меняет статус (`sent` → `delivered`) | 0 |
| Завершён | Продана, скрывается | 0 |
| Возврат | Джинса «возврат едет» (`returnTransit`), на плитке «+1» | 0 |
| Возврат на проверке | Джинса «возврат на складе, нужно разобрать» (`returnStock`) | 0 |
| На складе | Возврат разобран, джинса на полку своей поставки | +1 |
| Брак | Списание | 0 (уходит из учёта) |

Номер заказа у джинсы на складе (`Unit.order`) — номер Авито, строкой.

**Сверка** (`shared/fulfillment/reserve.ts`, `syncReserves`) делает резервы, снятие резервов и пометки проблем.
Запускается при старте приложения и после каждого изменения заказов или склада — на любом экране. Повторный
запуск ничего не меняет. Заказы обходятся от старых к новым: кто раньше заказал, тому и джинса. Пришла поставка —
заказы с «Нет на складе» сами встают в резерв. Сейчас сверка делает резерв (Заказан / Собран), снятие резерва
(Отменён) и пометки; статус джинсы после отправки (`sent`, `delivered`, возвраты) пока из заказа не выводится.

### Комплектация и пульт

Полностью — [PICKING.md](PICKING.md). Коротко:

```
Заказан + проблема                    → Проблема      (в очередь не идёт)
Заказан + резерв, не в партии         → К печати      (очередь печати)
Заказан + в партии на пульте          → В партии / Напечатан
«Партия расклеена» без ошибки         → Собран
«Партия расклеена» с ошибкой          → снова К печати
```

Этапы считаются (`orderStage`), отдельно не хранятся. Комплектация собирает очередь и отправляет партии на пульт,
пульт печатает и ставит «Собран».

## 8. Как считаются цифры на экране

- **Период** — по дню `createdAt` в местном времени, границы включительно: «Сегодня» — сегодняшний день,
  «7 дней» — сегодня и 6 дней назад, «30 дней» — сегодня и 29 назад, «Всё время» — без ограничения,
  «Период…» — от и до (пустая граница — без ограничения).
- **Счётчики на чипах** — сколько заказов этой группы в выбранном периоде. Поиск на счётчики не влияет.
- **Группы чипов** (`GROUPS` в `statuses.ts`): Активные — всё, кроме закрытых; Проблемы — есть `problem`;
  К сборке — Заказан; Собран; В пути — Отправлен + В доставке; В ПВЗ — Приехал; Возвраты — Возврат +
  Возврат на проверке; Закрытые — Завершён, Отменён, На складе, Брак. «К сборке» включает и заказы с проблемой.
- **Поиск**: в запросе есть цифры — ищем по номеру Авито (подстрока, пробелы игнорируются), иначе — по названию
  товара без учёта регистра. Поиск идёт по всем заказам, без группы и периода.
- **Список**: новые сверху по `createdAt`, по дням; заголовок «Сегодня» / «Вчера» / «12 ноября» (год — только
  если не текущий) и количество за день.
- **Номер** показывается группами по три с узким пробелом: `4 812 339 102`.

## 9. Экран «Заказы»

Сверху вниз:

1. **Шапка:** «Заказы», подпись про тестовые данные, справа поиск «Номер Авито или товар».
   Пока в поиске что-то есть, чипы групп не подсвечены и под фильтрами подпись «Ищем по всем заказам, фильтры
   не действуют». Клик по чипу группы очищает поиск.
2. **Чипы групп со счётчиками** (раздел 8). По умолчанию «Активные». «Проблемы» с красной подложкой, пока есть
   хоть одна.
3. **Период:** Сегодня · 7 дней · 30 дней · **Всё время** (по умолчанию) · Период… (две даты). «Всё время» по
   умолчанию, чтобы старый, но ещё едущий заказ не пропадал из «Активных».
4. **Список по дням.** Строка: товар и размер чёрным чипом (размера нет — чипа нет); ниже `№ номер · время · служба · 1 652 ₽` (сумма «вам», если есть);
   справа бейдж статуса, бейдж проблемы и «Спорный». На телефоне (≤ 640 px) бейджи переезжают под текст.
5. **Клик по строке** плавно раскрывает её на месте (`Collapse`): слева поля в две колонки (номер Авито, когда
   заказан, товар, размер или «Нет — выберите ниже», служба, номер отправления группами, отгрузить до, «Вам»;
   под полями «Подробнее ▾» — из чего сложилась сумма: цена объявления, скидка Авито, продано за, удержал Авито
   (комиссия и прочее), вам; суммы как их пишет Авито, разницы — просто вычитание;
   у «Заказан» под полями выбор размера с подтверждением (раздел 6), ниже ссылка «Чат с покупателем ↗», если
   есть чат), справа «История» — лента статусов с датой и временем,
   текущий жирным. Открыт один заказ за раз, повторный клик закрывает.
6. **Пусто:** «Заказов нет» или при поиске «Ничего не нашли».

### Цвета статусов

| Тон | Статусы |
|---|---|
| Внимание (жёлтый) | Заказан, Отправлен, В доставке, Возврат |
| Готово (зелёный) | Собран, Приехал, На складе |
| Проблема (красный) | пометки проблем, Возврат на проверке (ждёт нашего действия) |
| Нейтральный (серый) | Завершён, Отменён, Брак |

Статус всегда подписан текстом (`StatusBadge`), цвет — подсказка. Токены — `--warning-*`, `--success-*`,
`--danger-*`, `--neutral-*` в `tokens.css` (описаны в DESIGN.md).

## 10. Хранение и тестовые данные

  (удобство одного браузера).
