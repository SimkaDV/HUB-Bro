# Расширение «HUB BRO — заказы Авито»

Расширение Chrome, которое забирает заказы из кабинета Авито и передаёт их в кабинет HUB BRO. Нужно, пока нет
Доставки для бизнеса и официального API заказов ([ORDERS.md](ORDERS.md), раздел 2). Код — папка `extension/`
в корне репозитория, кабинетная часть — `web/src/shared/avito/` и `web/src/shared/orders/avitoImport.ts`.

**Как пользоваться документом:** перед работой с расширением или приёмом заказов из него читай его и
ORDERS.md; после изменений обнови разделы и журнал внизу в том же коммите.

---

## 1. Как работает

```
 avito.ru/orders ─ кнопка «Собрать заказы» ─┐
                                            ├─► collect.js: внутренний JSON Авито под входом продавца
 кабинет «Подтянуть из Авито» ─► фон ───────┘        (вкладка Авито; нет — откроется фоном и закроется)
                                                       │
                                               пачка заказов
                                                       │
            фон: держит пачку, пока кабинет не подтвердит приём (pending)
                                                       │
            hub.js на сайте ─► кабинет: слияние по номеру Авито, без дублей
                                                       │
            запасной путь: «Скопировать» на Авито → Настройки → Расширение Авито → «Принять заказы»
```

- **Плашка на Авито** (справа внизу на странице заказов, сворачивается):

  ```
  HUB BRO · BRO x BRO SHOP          свернуть
  ☑ Ждут отправки             16
  ☑ Едут к покупателю         34
  ☑ Ждут в ПВЗ                27
  ☐ Возвраты и спорные         8
  ☐ Завершены (14 дней)       41
  ☐ Отменены (14 дней)        12
  ☐ Считать сразу при открытии страницы
  ☐ Дочитывать товары и у остальных групп (дольше)
  [Посчитать] [Собрать отмеченные (77)] [Скопировать]
  запросов 14 · 429: 0            журнал запросов
  ```

  1. **«Посчитать»** — только списки (карточки не открываем): сколько заказов в каждой группе. Со включённым
     «Считать сразу» — само при открытии страницы (кроме вкладки, которую фон открыл для кнопки из кабинета).
  2. **Галочки** — какие группы собрать. По умолчанию «Ждут отправки», «Едут», «В ПВЗ». Запоминаются.
  3. **«Собрать отмеченные (N)»** — пачка только из отмеченных групп → в кабинет. Итог: «Собрано 77. Передано
     в кабинет» или «Кабинет не открыт — передам, когда откроете»; «Скопировать» — запасной путь.
  4. **Журнал запросов** — внизу «запросов N · 429: M · ждали K с», ссылка копирует журнал последнего прогона
     (время, тип запроса, ответ, `Retry-After`) — чтобы понять, где Авито начинает резать.
- **Кнопка в кабинете:** «Подтянуть из Авито» на экране «Заказы» — собирает группы, отмеченные на плашке.
  Ход сбора и итог — строкой под шапкой.
- **Кабинет закрыт:** пачка ждёт в расширении и приходит, как только кабинет откроют. Кабинет подтверждает
  приём, тогда пачка стирается. Повторная пачка ничего не дублирует.

## 2. Что собирает

| Группа | Фильтры списка Авито |
|---|---|
| Ждут отправки | `waiting_confirmation`, `waiting_shipment` |
| Едут к покупателю | `in_transit` |
| Ждут в ПВЗ | `delivered_in_pvz` |
| Возвраты и спорные | `on_return`, `disputed` |
| Завершены (14 дней) | `payout_wait`, `finished` — по `updatedAt` за 14 дней |
| Отменены (14 дней) | `canceled` — за 14 дней |

| Запрос | Что берём |
|---|---|
| `/web/1/profiles/list` | Текущий аккаунт Авито (`profileId`, имя) — в пачке, чтобы не смешать магазины |
| `/web/1/orders?action=sell&status=<фильтр>&page=N` | Списки: номер, статус, служба, трек, срок, сумма, чат, название (`imgSet[0].alt`) |
| `/web/2/profile/order?referenceID=<номер>` | Карточка: товары (`items`: id объявления, название, цена продажи, `oldPrice` — цена объявления), номер отправления, срок |

- Берём только заказы, где мы продавец (`userKind: seller`).
- **Карточки открываем только там, где без них никак:** «Ждут отправки» без номера отправления (у «Авито» он
  только в карточке; Авито выдаёт его не сразу — без номера перечитываем не чаще раза в 30 минут). Для
  статусов остальных групп хватает списка; их товары — только с галочкой «Дочитывать товары».
- Подсчёт живёт 5 минут: «Собрать» в эти 5 минут не перечитывает списки.
- Карточки кэшируются в `chrome.storage.local` (по аккаунту) и сохраняются по ходу. Не больше 30 карточек за
  сбор — сначала ждущие отправки, потом новые; остальные — в следующие разы.
- **429 (Авито режет частые запросы).** Пауза перед каждым запросом: 0,7 с список, 1,2 с карточка. На 429 —
  ждём (`Retry-After` или 10 → 30 → 60 с) и повторяем, а темп до конца прогона вдвое медленнее (до ×4). Не
  помогло — подсчёт останавливается с ошибкой «Авито просит паузу», на карточках пачка уходит частичной
  (`missingDetails`).
- Не больше 25 страниц на фильтр. Запросы — только по кнопке (или «Считать сразу»). Телефон и адрес покупателя
  не берём.
- Настройки плашки — `chrome.storage.local.settings`: `groups`, `autoCount`, `readItems`, `collapsed`. Журнал
  последнего прогона — `journal`.

### Пачка (`hubbro.avito-orders`, версия 1)

`{ kind, version, collectedAt, account: { id, name }, orders: AvitoOrder[] }`, где у заказа: `orderId`,
`createdAt`, `updatedAt`, `status` / `statusLabel`, `provider` / `providerLabel`, `trackingNumber`, `info`,
`payout`, `chatId`, `itemsCount`, `title`, `items`, `dispatchNumber`, `shipBy` («19 ноября»). У пачки ещё
`groups` — какие группы собраны,
`missingDetails` — скольким заказам не дочитали карточку, и `stopped` — почему остановились раньше. Тип — `AvitoOrder`
в `shared/orders/avitoImport.ts`.

## 3. Приём в кабинете

`mergeAvitoBatch` (чистая функция) — ключ номер Авито:

- **Новый номер** — заказ «Заказан» с историей с даты заказа, сразу статус Авито (`applyAvitoStatus`). Товар —
  название объявления (`items[0].title`), пока нет привязки объявлений к моделям склада.
- **Знакомый номер** — обновляем только поля Авито: служба, номер отправления, срок, объявление, чат, время
  сверки — и статус по правилам ORDERS.md (назад не ходим, закрытые не трогаем). Размер, товар и наше не трогаем.
- **Заказов нет в пачке** — не трогаем и не удаляем.
- **Не взяли:** служба, которой у нас нет. **Взяли с предупреждением:** незнакомый статус (статус не меняем),
  несколько товаров в заказе, не дочитанные карточки («подтяните ещё раз через пару минут»). Всё это — строками
  под итогом.

## 4. Мост кабинет ⇄ расширение

`window.postMessage` на странице кабинета — `https://hub-bro.vercel.app`, `https://taylormomsen.tailccfeb1.ts.net`
(свой сервер по Tailscale, ARCHITECTURE.md) или `http://localhost:5173` (дев-сервер),
только с того же окна и источника. Адреса перечислены в трёх местах (добавить адрес нового клиента во все три — `node extension/set-hub.mjs https://адрес`;
это же делает `avito/deploy.sh`): `manifest.json` (`host_permissions`,
`content_scripts` для `hub.js`) и `HUB_URLS` в `background.js`. Маску `*.vercel.app` не ставим — пачки заказов
уходили бы на любой чужой сайт на Vercel. Открыты и сайт, и localhost — пачка придёт в обе вкладки, на сервер её
запишет сайт.

| Кто → кому | Сообщение |
|---|---|
| кабинет → расширение | `{ source: "hubbro-page", type: "hello" }` при старте · `collect` · `ack, id` |
| расширение → кабинет | `{ source: "hubbro-ext", type: "ready", version }` · `progress, text` · `batch, id, batch` · `error, message` |

`startAvitoBridge()` вызывается в `main.tsx`: пачки принимаются на любом экране. Состояние связи —
`useAvitoLink()` (версия расширения, идёт ли сбор, ошибка, итог последнего приёма).

## 5. Установка

Сайт видит расширение **0.2.0 и новее**; 0.1.0 работало только с localhost.

1. Взять свежую папку `extension` из проекта (после `git pull` или из архива репозитория).
2. `chrome://extensions` → «Режим разработчика» (справа сверху).
3. «Загрузить распакованное» → папка `extension`. Уже стоит 0.1.0 — заменить папку и нажать «Обновить» (круглая
   стрелка) у расширения, версия станет 0.2.0. Chrome может спросить доступ к `hub-bro.vercel.app` — разрешить.
4. Войти в Авито в этом же Chrome, открыть https://hub-bro.vercel.app → Настройки → «Расширение Авито» —
   «На связи», «Расширение 0.2.0 на связи…».

Обновление: заменить папку и нажать «Обновить» у расширения. Работает и в Яндекс.Браузере. Позже — Chrome Web
Store «по ссылке», чтобы обновлялось само.

## 6. Риски

- Это внутренний API сайта: Авито может поменять его без предупреждения. Тогда сбор пишет «Авито поменял
  страницу — обновите расширение», в заказы ничего не пишется.
- Сменится адрес сайта (свой домен) — поправить все три места (раздел 4), поднять версию и обновить расширение
  на всех компах, иначе «Не установлено».
