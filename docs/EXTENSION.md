# Расширение «HUB BRO — заказы Авито»

Расширение Chrome, которое забирает заказы из кабинета Авито и передаёт их в кабинет HUB BRO. Нужно, пока нет
Доставки для бизнеса и официального API заказов ([ORDERS.md](ORDERS.md), раздел 2). Код — папка `extension/`
в корне репозитория, кабинетная часть — `web/src/shared/avito/` и `web/src/shared/orders/avitoImport.ts`.

**Как пользоваться документом:** перед работой с расширением или приёмом заказов из него читай его и
ORDERS.md; после изменений обнови разделы и журнал внизу в том же коммите.

---

## 1. Как работает

```
 avito.ru/orders ─ кнопка «Собрать заказы» ─┐
                                            ├─► collect.js: внутренний JSON Авито под входом продавца
 кабинет «Подтянуть из Авито» ─► фон ───────┘        (вкладка Авито; нет — откроется фоном и закроется)
                                                       │
                                               пачка заказов
                                                       │
            фон: держит пачку, пока кабинет не подтвердит приём (pending)
                                                       │
            hub.js на localhost:5173 ─► кабинет: слияние по номеру Авито, без дублей
                                                       │
            запасной путь: «Скопировать» на Авито → Настройки → Расширение Авито → «Принять заказы»
```

- **Кнопка на Авито:** плашка «HUB BRO · Собрать заказы» справа внизу на странице заказов. Показывает ход сбора,
  итог («Собрано 24. Передано в кабинет» или «Кабинет не открыт — передам, когда откроете») и «Скопировать».
- **Кнопка в кабинете:** «Подтянуть из Авито» на экране «Заказы». Ход сбора и итог — строкой под шапкой.
- **Кабинет закрыт:** пачка ждёт в расширении и приходит, как только кабинет откроют. Кабинет подтверждает
  приём, тогда пачка стирается. Повторная пачка ничего не дублирует.

## 2. Что собирает

| Откуда | Что |
|---|---|
| `/web/1/profiles/list` | Текущий аккаунт Авито (`profileId`, имя) — в пачке, чтобы не смешать магазины |
| `/web/1/orders?action=sell&status=<фильтр>` | Все страницы фильтров «незакрытых»: `waiting_confirmation`, `waiting_shipment`, `in_transit`, `delivered_in_pvz`, `payout_wait`, `on_return`, `disputed`. Закрытые `finished`, `canceled` — за последние **14 дней** (по `updatedAt`) |
| `/web/2/profile/order?referenceID=<номер>` | Карточка: товары (`items`: id объявления, название, цена, количество), номер отправления, срок отгрузки |

- Берём только заказы, где мы продавец (`userKind: seller`).
- Карточки кэшируются в `chrome.storage.local` (по аккаунту). Перечитываются только новые заказы и те, у кого
  ещё нет номера отправления, пока их можно отправить.
- Пауза 250 мс между запросами, не больше 25 страниц на фильтр. Запросы — только по кнопке.
- Телефон и адрес покупателя не берём.

### Пачка (`hubbro.avito-orders`, версия 1)

`{ kind, version, collectedAt, account: { id, name }, orders: AvitoOrder[] }`, где у заказа: `orderId`,
`createdAt`, `updatedAt`, `status` / `statusLabel`, `provider` / `providerLabel`, `trackingNumber`, `info`,
`payout`, `chatId`, `itemsCount`, `items`, `dispatchNumber`, `shipBy` («19 ноября»). Тип — `AvitoOrder`
в `shared/orders/avitoImport.ts`.

## 3. Приём в кабинете

`mergeAvitoBatch` (чистая функция) — ключ номер Авито:

- **Новый номер** — заказ «Заказан» с историей с даты заказа, сразу статус Авито (`applyAvitoStatus`). Товар —
  название объявления (`items[0].title`), пока нет привязки объявлений к моделям склада.
- **Знакомый номер** — обновляем только поля Авито: служба, номер отправления, срок, объявление, чат, время
  сверки — и статус по правилам ORDERS.md (назад не ходим, закрытые не трогаем). Размер, товар и наше не трогаем.
- **Заказов нет в пачке** — не трогаем и не удаляем.
- **Не взяли:** служба, которой у нас нет. **Взяли с предупреждением:** незнакомый статус (статус не меняем),
  несколько товаров в заказе. Всё это — строками под итогом.
- **Первые живые заказы:** кабинет спрашивает «Убрать тестовые заказы и тестовые партии печати?» (один раз за
  открытие). Да — тестовые заказы (без `syncedAt`) удаляются, их резервы возвращаются на полку, партии печати
  очищаются (`removeTestOrders`).

## 4. Мост кабинет ⇄ расширение

`window.postMessage` на `localhost:5173`, только с того же окна и источника:

| Кто → кому | Сообщение |
|---|---|
| кабинет → расширение | `{ source: "hubbro-page", type: "hello" }` при старте · `collect` · `ack, id` |
| расширение → кабинет | `{ source: "hubbro-ext", type: "ready", version }` · `progress, text` · `batch, id, batch` · `error, message` |

`startAvitoBridge()` вызывается в `main.tsx`: пачки принимаются на любом экране. Состояние связи —
`useAvitoLink()` (версия расширения, идёт ли сбор, ошибка, итог последнего приёма).

## 5. Установка

1. `chrome://extensions` → «Режим разработчика» (справа сверху).
2. «Загрузить распакованное» → папка `extension` из проекта.
3. Войти в Авито в этом же Chrome, обновить кабинет — в Настройках «Расширение Авито» станет «На связи».

Обновление: заменить папку и нажать «Обновить» у расширения. Работает и в Яндекс.Браузере. Позже — Chrome Web
Store «по ссылке», чтобы обновлялось само.

## 6. Риски

- Это внутренний API сайта: Авито может поменять его без предупреждения. Тогда сбор пишет «Авито поменял
  страницу — обновите расширение», в заказы ничего не пишется.
- Кабинет только на `localhost:5173`. Будет домен — добавить его в `manifest.json` (`host_permissions`,
  `content_scripts`).
